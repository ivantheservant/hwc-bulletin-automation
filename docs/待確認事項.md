### 7-1. 為了做 Word 範本，放寬了「全 `src/` 不准用 `DriveApp`」這條 lint 規則

**背景**：`tools/lint-readonly-roster.js` 原本第 3 條規則是「全 `src/`
一律不准出現 `DriveApp`」，當時的註解寫明「日後真的需要才另外設計審查」。

prompt7 §4 明確要求 `readTemplateBlob_(fileId)` 用
`DriveApp.getFileById(fileId).getBlob()`，沒有 Drive 根本做不到。

**我的決定**：把規則 3 由「全面禁止」改成「**只准出現在
`src/DocxIo.gs`**」，手法跟既有的規則 1（`openById(` 只准出現在
`RosterRead.gs`）完全一樣——把能力鎖死在單一檔案，「有沒有人用 Drive
繞過職事表唯讀邊界」永遠只需要審一個檔案。

同時**新增規則 4**作為第二道防線：`DocxIo.gs` 內不准出現
`ROSTER_SPREADSHEET_ID`。理由是 `DriveApp.getFileById()` 理論上可以開啟
任何檔案（包括職事表本身），靜態上證明不了「某個執行期變數不是職事表
ID」，但可以證明「這個檔案從來拿不到職事表 ID 這個設定鍵」。

**要不要改**：如果 Ivan 覺得這個放寬不可接受，替代方案是由 Ivan 每次
人手把範本內容貼進試算表某一格（極不實際），或者改用 Apps Script 的
進階 Drive 服務（同樣要開權限，而且更難靜態稽核）。我認為目前的做法是
風險最低的一種。

⚠️ **日後任何人再想放寬這條規則，請先讀 `tools/lint-readonly-roster.js`
檔頭的完整說明。**

第 3 部分（`SELFCHECK_MAX_ROWS` 整體額度截斷）都要求截斷時寫「尚有 N
項未列出」／「尚有 N 個主日未列出」，但沒有明講第一個的 `N` 是指「被
截掉的主日數」還是「被截掉那些主日總共有幾多個待填欄位」。

**我的決定**：
- `SELFCHECK_MISSING_DETAIL_ROWS` 截斷（`selfCheckCapMissingSummary_()`）：
  `N` = 被截掉那些主日的**待填欄位總數**（例如 5 個主日各 20 項，
  `N=100`），用詞是「尚有 N **項**未列出」——跟這個項目本身的結論句
  「266 **項**待填」用同一個單位，讀的人不用換算。
- `SELFCHECK_MAX_ROWS` 整體額度截斷（`buildSelfCheckReportLines_()`
  裡的 `selfCheckDetailTruncationTrailer_()`）：`N` = 被截掉的**彙總
  行數**（此時每一行已經是一個主日），用詞是「尚有 N **個主日**未
  列出」——這裡的截斷單位天生就是「一行＝一個主日」，跟欄位數無關。

  兩者用詞刻意不同（「項」vs「個主日」），就是為了不要讓 Ivan 誤會
  兩個數字是同一回事。

**理由**：prompt 本身也用了兩種不同措辭（「尚有 N 項未列出」／
「尚有 N 個主日未列出」），我判斷這不是巧合，而是刻意區分兩層截斷各自
的單位——第 2 部分的截斷發生在「決定要不要顯示這個主日的彙總」，跟
「這個主日有幾多項」直接相關；第 3 部分的截斷發生在「連彙總行本身都
放不下」，這時候在意的是「還有幾多行／幾多個主日沒印出來」，跟每行
背後的欄位數無關。

**要不要改**：如果 Ivan 覺得兩處應該統一成同一個單位，改
`selfCheckCapMissingSummary_()` 或 `selfCheckDetailTruncationTrailer_()`
其中一處的計數方式即可，不影響整體架構。

### H-1. 副框「同一列兩格皆空就刪整列」寫成通則，不是只針對第 3 列

**背景**：prompt 第 2 部分的規則 1 寫「**第 3 列**兩個欄位皆空 → 刪除
整列」，規則 2 寫「六個欄位全部皆空 → 刪除整個表格」，沒有明講第 1、2
列兩格皆空時應該怎樣。

**我的決定**：`applyOptionalLabelledCellRows_()` 實作成**通則**——
**任何**一列兩格皆空就刪那一列，全部列都要刪就改為刪整個表格。

**理由**：規則 1 點名第 3 列，我判斷是因為那是現實中最常見的情況
（`2026-04-05` 那期沒有孩童奉獻禮），不是因為第 1、2 列有特殊待遇。
「標籤不可以孤零零留在紙上」這個理由對三列完全一樣適用；如果只保護
第 3 列，某一期剛好沒有入會禮的話，紙上就會出現一行「受浸肢體：」
「入會肢體：」兩個空標籤——同一個問題，只是換了一列。

另外，規則 2 如果照字面實作成「六格全空才刪表格」，而規則 1 又逐列
刪走三列，結果會剩下一個**空表格**——空表格既難看，亦容易踩中
`docs/已知bug類型.md` 事故十六（Word 判定檔案損毀）。所以我把兩條規則
接起來：全部列都要刪的時候，直接刪整個表格。

**額外保險**：只有「那個表格內的列**全部**都在副框的分組內」才會整個
刪走。萬一日後範本在副框加一行標題列，系統只會刪空的那幾列，不會連
標題一齊丟掉（`tests/baptismbox.test.js` 的「邊界 c」鎖住這一點）。

**要不要改**：如果 Ivan 確認第 1、2 列即使兩格皆空也要保留（例如版面
上需要固定高度），改 `applyOptionalLabelledCellRows_()` 讓 `rowGroups`
每一項多帶一個「可不可以刪」的旗標即可。

**為什麼這樣比字面規則更嚴**：字面規則可以被「寫了參數但寫錯值」
（`supportsAllDrives: false`）滿足；而兩條規則合起來，是**同時**要求
「呼叫點走單一真相來源」與「那個真相來源真的對」。由
`tests/publishfix.test.js` 第 3b 條專門驗這一條（包裝漏掉參數也要被捉到）。

**要不要改**：無需改動。

### M-4. 防重複用 `PropertiesService`，不用 `PublishLog.PUBLISHED_AT`

**背景**：prompt 要求「若同一個主日在 `PUBLISH_DEDUP_SEC`（預設 30）秒內
已經成功發佈過，第二次直接回傳『剛才已經發佈過（第 N 版）』」。

**我的決定**：時間戳記存在 `PropertiesService` 的**指令碼層**屬性
（`PUBLISH_LAST|<主日>`），不從 `PublishLog` 讀。

理由：`PublishLog.PUBLISHED_AT` 讀回來要經 Sheets 的型別正規化，秒級
精度不可靠；而這裡要比的正正是「幾秒之內」。ScriptProperties 存一個純
毫秒數，兩邊都沒有歧義，而且不用為了一個防呆判斷多讀一次工作表。

**副作用**：`LockService` 與這個時間戳記**兩者都要**。鎖擋得住「兩個
請求同時進來」，擋不住「一個做完、使用者見不到反應又撳一次」——那兩次
之間隔了整個第一次的執行時間，鎖早就放回去了。

**要不要改**：無需改動。想關掉防重複，把 `PUBLISH_DEDUP_SEC` 設成 `0`。

### M-6. `uniqueOutputFileName_()` 查不到同名時，直接用時間戳記

### M-7. 逾時之後**不叫**使用者重試

## N. 使用者測試前收尾（prompt-pre-usertest.md）

### N-1. 範本內兩個異體字——需要 Ivan 在 Word 用「尋找及取代」修正

**背景**：`TPL_NORMAL`、`TPL_COMBINED_BAPTISM`、`TPL_ANNIVERSARY` 三個範本
的聚會時間欄（原稿內容），各自有兩個字用了錯誤的 Unicode 異體字：

| 錯誤字元 | 錯誤碼位 | 應該是 | 正確碼位 | 出現位置 |
|---|---|---|---|---|
| ⾧ | U+2FA7（康熙部首，Kangxi Radical Long） | 長 | U+9577 | 「粵語⾧者」 |
| ㇐ | U+31D0（CJK 筆畫，CJK Stroke H） | 一 | U+4E00 | 「除第㇐週外」 |

視覺上跟正確字完全看不出分別（字型會照樣渲染成看似正常的字），但複製、
搜尋、螢幕朗讀軟件會出問題——例如把「粵語⾧者」複製到搜尋列找「長者」
會找不到，朗讀軟件可能讀出完全不同的字。

**我的決定**：**不改 `.docx` 範本**（prompt 明文禁止，範本由 Ivan 管理）。
改為：

1. 在渲染管線加一個保險——`normalizeVariantCharacters_()`
   （`src/DocxTemplate.gs`），輸出前把這兩個異體字正規化成正確的字，
   `renderDocumentXml_()` 的 `stats` 帶 `variantCharsReplaced`／
   `variantCharsBreakdown`。
2. 真的替換過（`count > 0`）就寫一份 Diagnostics 報告
   「異體字正規化」，講明主日、檔名、各替換了幾次
   （`buildVariantCharsReportLines_()`，`src/BulletinRender.gs`）。
3. 在這裡記一則，等 Ivan 有空時直接在 Word 開啟三個範本檔案，用
   「常用 ▸ 尋找 ▸ 取代」（或 Ctrl+H），把 `⾧` 取代成 `長`、`㇐` 取代成
   `一`——**兩個都要用「尋找及取代」，不要用眼睛看着手動刪字重打**，
   因為視覺上完全看不出分別，手動打字打出來的十居其九仍然是隨手選字法
   選出來的另一個異體字，而不是真正的正確字。

**為什麼 Diagnostics 而不是 ErrorLog**：`ErrorLog` 是「系統偵測到的例外
狀況」，但只要範本一日未改好，這個替換**每一次產生週報都會發生**——
不是異常，是意料之內、而且已經被安全網接住的事。寫進 `ErrorLog` 會令
它看起來像個持續發生的錯誤，洗版真正的例外記錄。`Diagnostics` 定位是
「最新一次操作的報告」，跟「範本佔位符檢查」「本季週報產生」等既有報告
同一類——只保留最新一次，這是它本來的設計（見 `src/Diagnostics.gs`
檔頭），跟這裡的用法一致。

**副作用（已知取捨）**：因為 `Diagnostics` 只保留最新一次寫入的報告，
如果「產生本週週報」之後緊接著跑「完成度自我檢測」之類的其他報告，
這一份「異體字正規化」提示就會被蓋掉，只留在對話框裏看過一次。這跟
「範本佔位符檢查」的既有行為一致，不是這一輪新引入的落差。真正持久的
提醒是**這一則待確認事項**與範本本身尚未修正這個事實——只要範本一直
沒改，下一次產生又會再寫一次。

**要不要改**：**這是需要 Ivan 動手的一步**——請開啟三個 `.docx` 範本，
用「尋找及取代」修正上面兩個字元。修正之後 `variantCharsReplaced` 會
變回 0，這個保險與 Diagnostics 報告都會自然停止出現，不需要另外關掉
任何開關。

### N-3. DRY_RUN 底下發佈前的提醒，怎樣跟 R-006／R-007 的「強制發佈」分開
