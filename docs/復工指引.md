⚠️ **由 R-038 起，日常操作以填寫介面為主。** 下面八項在填寫介面
「季度作業」區塊（摺疊，在「發佈及匯出」上面）都有一粒對應的按鈕，

- `發佈版本記錄` — 發錯了靠它還原

**維護**

- `deploy.bat` 一鍵部署

### 重要規矩
1. **職事表一格都不可以寫**
2. **原始碼不可以寫死任何 ID、電郵、姓名、日期、行數**，一律經 `Config`
3. **不刪行**，只用 `ACTIVE=FALSE` 或 `ARCHIVED=TRUE`
4. 工作表結構：第 1 行中文標題、第 2 行機器鍵、第 3 行起是資料
5. `DRY_RUN` 平時保持 `TRUE`
6. `PUBLISHED_PDF_FILE_ID` **絕對不可以**等於 `SELFTEST_MASTER_PDF_FILE_ID`
7. **`getUi()` 不可以出現在 Web App 路徑上**——Web App 沒有 UI，一叫就爆。
   選單與介面共用的核心（`src/QuarterOps.gs`）整個檔案一行都不可以有
8. **填寫介面不可以寫 `Diagnostics`**——那張表每次清空重寫，只保留最新
   一份；幹事撳一下就會清走 IT 剛跑完的診斷報告

### 已知 bug 類型（寫任何東西之前自問）
1. `.html` 註解裏不可以出現字面上的樣板標籤符號
2. 缺失被當成正常值靜靜過
3. 同一個狀態有兩個真相來源，只更新了其中一個
4. 由工作表讀出來的 Date／boolean 未經處理就用
5. 測試直接叫內部函式，沒有一個由真正入口叫下去
6. Shared Drive 上的 Drive 進階服務要 `supportsAllDrives`，否則 404
7. 前端沒有失敗處理，等於後端錯誤全部消失
8. 有副作用的檢查不可以當成不變量
9. 不變量假設了只有正式環境存在
10. 斷言指定了「用哪一道守門」，而不是「結果對不對」
11. 報告被自己的明細擠爆
12. 驗證函式與被驗證的邏輯用同一個假設，等於沒有驗證
13. 「決定處理哪一季」的退回鏈，不可以用來決定「去外部系統拿哪一季的資料」
14. 最敏感的設定表反而沒有稽核
15. 續跑用了沒有狀態的亂數，等於每次都是新的一輪
16. **斷言依賴真實時間流逝，而測試跑得比它快**
17. **同一道濾網接上問題不同的呼叫點**（三對一錯，最難查）

## 七、人手測試清單（自測機做不到的）

**這些是真的有需要，不是為了幫你記起系統。**

### 高優先（向堂委、執事簡報之前）

**1. 內容填滿之後的版面（同時是 R-032 的校準）**
揀一個主日，分兩次填：
- 第一次：家事報告 **6 條**、代禱 3 條、財政填滿、團契 4 行、人數 12 格 → 記頁數
- 第二次：家事報告加到 **10 條**、代禱加到 5 條 → 記頁數
- 記低**由 4 頁變 5 頁是在第幾條家事報告時發生**

那個數字是 `BULLETIN_CONTENT_WARN_CHARS` 唯一的校準來源。
另外要留意：我們的範本把家事報告放在**正文段落**，真週報放在**表格內**，
表格跨頁斷開的行為不同，要看清楚有沒有走位。

**2. 印出來對比現行印刷版**
A5 兩頁排一張 A4 雙面印，同一週的舊週報放旁邊比。自測機只驗 XML 屬性，
驗不到紙上的觀感。

**3. 星期一觸發器（R-028）**
自測機明確寫住驗不到——那支函式會為真實季度建立填寫表，違反沙盒規則。
做法：觸發時間暫改十分鐘後 → 等它自己跑 → 看 `SendLog` 與 `ErrorLog` → 改回星期一。

**4. master 連結在教會外面開得開**
登出狀態的瀏覽器、iPhone、Android 各開一次。會眾不在教會網域內，自測機驗不到。

**5. 兩個人同時改同一個主日**
兩個瀏覽器兩個帳戶，同時開同一個主日同時儲存，應該有一個被樂觀鎖擋住。
自測機是單執行緒，驗不到。

### 中優先

**6. 由堂委角度填內容表** — 使用性問題，程式驗不到。特別看「連續到」好不好用。

**7. 發佈錯了怎樣救** — 故意發佈一份錯的，用「發佈版本記錄」加 Drive 還原，記低步驟。

**8. 真實寄給多過一個人** — `Recipients` 補齊之後，`DRY_RUN` 改 `FALSE`，
寄給兩三個人，確認收得到，然後**立即改回 `TRUE`**。
（單一收件人已於 2026-08-20 驗過。）

### 不用做的
產生 Word 的正確性、佔位符殘留、匯入冪等、唯讀欄位擋、防重複、
下一個主日推算、封存與取消封存、預覽頁——自測機每次都跑。

## 八、十分鐘自檢（每次復工先做）

1. 開 Web App，見到填寫介面 → 部署仍然有效
2. 選單 ▸ **完成度自我檢測** → 🔴 應該是 0

4. 選單 ▸ **上線前檢查（唯讀）** → 🔴 應該是 0
5. 選單 ▸ **跑自測** ▸ 續跑至完 → 預期 38 PASS、1 SKIPPED（S25）、0 FAIL

與 S25（要沒有夏令轉換）必然有一組報「不適用」。

五項都過就可以繼續開發。

## 九、常見陷阱

- **初始化工作表要在開 Web App 之前**，否則 schema 不符會報錯
- **`Diagnostics` 每次執行清空重寫**，跑多樣東西要逐項抄低摘要
- **改過 `.html` 一定要重新部署**，否則介面不會更新
- **`deployment-id.txt` 不在 git 內**，換電腦要用 `clasp deployments` 重建
- **不要在 Apps Script 編輯器手動加 Drive 服務**，`appsscript.json` 已經有，
  加多一次會報「service identifier used more than once」
- **`WEBAPP_ALLOWED_EMAILS` 鎖不到部署者**（已修），但清單建議加入自己
- 自我檢測的六個黃燈目前全部是預期的：`Recipients` 未補、測試季待填、
  `ErrorLog` 舊記錄、兩條不變量驗證不到、職事表缺口、未完成需求
