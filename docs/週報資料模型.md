# 週報資料模型

本文件記錄 `buildBulletinModel_(isoDate)` 的輸出契約——**一份完整的週報
資料模型**：事奉框、程序表、下週事奉、人數表、各清單、待填欄位全部算好，
隨時可以交給下一輪的版面渲染。

對應原始碼：`src/BulletinModel.gs`（總組裝）、`src/DutyBox.gs`（事奉框）、
`src/ProgramTable.gs`（程序表）、`src/PersonDisplay.gs`（姓名與尊稱）、
`src/BulletinDiagnostics.gs`（兩個選單處理函式）。如果程式與本文件有出入，
以原始碼為準，並請回頭修正本文件。

建立日期：2026-08-20（第三輪：週報資料模型組裝）

---

## 本輪刻意不做的事

**完全不碰 Google Docs、PDF、`MailApp`、`ScriptApp.newTrigger`。** 這一輪

## 分層

```
buildBulletinModel_(isoDate)              真正入口（讀 Config 與全部工作表）
  ├─ readRosterSnapshot_(isoDate)          本週職事表快照
  ├─ readRosterSnapshot_(isoDate + 7)      下週職事表快照
  ├─ buildProgramTable_(week, snapshot)    程序表
  │    └─ buildProgramTableRows_()           純函式
  ├─ buildDutyBox_(snapshot, 1)            第 1 頁事奉框
  │    └─ buildDutyBoxRows_()                純函式
  ├─ buildDutyBox_(nextSnapshot, 3)        第 3 頁下週事奉
  └─ assembleBulletinModel_(input)         純函式：日期、標題、各清單、待填
```

每一層都有一個**純函式**版本，全部資料由呼叫方傳進來，不碰 Apps Script
服務——所以整套規則判斷都可以在 Node 直接測試（見 `tests/bulletinmodel.test.js`、
`tests/dutybox.test.js`、`tests/programtable.test.js`、`tests/persondisplay.test.js`）。

### 日期格式化為什麼要注入

`assembleBulletinModel_()` 收一個 `formatDate(date, pattern)` 函式：

- **正式路徑**由 `buildBulletinModel_()` 傳入以 `Utilities.formatDate()`
  為底的實作，完整支援 Config 內任何 Java SimpleDateFormat 樣式。
- **純函式層測試**用內建的 `formatDatePatternSimple_()`，只支援
  `yyyy`／`yy`／`MM`／`M`／`dd`／`d`。

這樣純函式層完全不用碰 Apps Script 服務，又不會為了測試方便而犧牲正式
路徑的正確性。

## 輸出形狀

```js
{
  ok, notConfigured, found,
  isoDate, weekOfMonth, quarterId,
  rosterVersionUsed, rosterIsOfficial,
  special,                       // 同職事表快照的 special
  templateId,
  header: { pageTitle, coverDate, attendanceHeading, attendanceDate,
            nextWeekHeading, nextWeekDate },
  dutyBoxPage1: [...],           // buildDutyBox_(snapshot, 1)
  program: [...],                // buildProgramTable_()
  attendance: { columns: [...], rows: [...] },
  nextWeekDuty: [...],           // buildDutyBox_(下週的 snapshot, 3)
  flowers: { thisWeek, nextWeek },
  announcements: [...],
  prayerBlock: { heading, items: [...] },
  finance: [...],
  fellowships: [...],
  missing: [ { field, label, reason } ],
  warnings: [...]
}
```

`ROSTER_SPREADSHEET_ID` 未設定時回 `{ ok:false, notConfigured:true, ... }`，
其餘欄位仍然形狀完整（`null`／空陣列），呼叫方不用逐層防呆。

### `header` 的日期與標題

| 欄位 | 來源 |
|---|---|
| `coverDate` | 主日日期，用 Config `DATE_FORMAT_COVER` 格式化 |
| `attendanceDate` | 主日日期**減 7 天**，用 `DATE_FORMAT_INLINE`；`BulletinWeeks.ATTENDANCE_DATE` 有填就以它為準 |
| `nextWeekDate` | 主日日期**加 7 天**，用 `DATE_FORMAT_INLINE` |
| `pageTitle` | `BulletinWeeks.PAGE_TITLE`，留空用 Config `DEFAULT_PAGE_TITLE` |
| `attendanceHeading` | `BulletinWeeks.ATTENDANCE_HEADING`，留空用 `DEFAULT_ATTENDANCE_HEADING` |
| `nextWeekHeading` | `BulletinWeeks.NEXT_WEEK_HEADING`，留空用 `DEFAULT_NEXT_WEEK_HEADING` |

### `dutyBoxPage1` 與 `nextWeekDuty`

每個元素：`{ label, text, postIds: [...], states: [...], isPending }`。

- `nextWeekDuty` 用**下一個主日**的職事表快照（`isoDate + 7 天`）＋第 3 頁
  規則。下一個主日不在職事表內（例如跨季而下一季未生成）→ 空陣列＋
  `NEXT_WEEK_NOT_IN_ROSTER` 警告，**不拋錯**。
- `state` 為 `NOT_APPLICABLE` 的崗位**整行不出現**；合併規則見
  `src/DutyBox.gs` 與 docs/職事表唯讀介面.md「崗位 slot 的四種狀態」。

### `program`

每個元素：`{ seqNo, itemName, content, posture, fullWidth, sourceRow }`。
`fullWidth` 為 true 的行 `posture` 一律清空（樣本內「祈禱會」「拍照」都
沒有立坐標記）。

範本挑選、`CONDITION`／`CONTENT_SOURCE` 求值、誦讀與宣召的規則見下面
「程序表的規則」。

### `attendance`

3 列（崇拜／祈禱會／兒童）× 4 欄（英語堂／粵語堂主堂／粵語堂北岸／
華語堂），**全部文字**——樣本出現過 `--` 與 `前:5 / 後:120` 這類值，
不是數字。粵語堂主堂那一欄的標題用 Config `CANTONESE_SUBCOLUMN_LABEL`。

## 程序表的規則

### 範本挑選

`BulletinWeeks.PROGRAM_TEMPLATE_ID` 有值就用它（人手指定優先）。留空時
按特別主日的標題／類型推斷，並把推斷結果**寫回 `BulletinWeeks`**、同時
記一筆 `AuditLog`（動作 `INFER_PROGRAM_TEMPLATE`）：

| 條件 | 範本 |
|---|---|
| `special.title` 或 `special.type` 含 Config `TEMPLATE_KEYWORDS_BAPTISM` 的任何一個關鍵詞 | `TPL_COMBINED_BAPTISM` |
| 含 `TEMPLATE_KEYWORDS_ANNIVERSARY` 的任何一個關鍵詞 | `TPL_ANNIVERSARY` |
| 其他（含沒有特別主日） | Config `TEMPLATE_DEFAULT` |

寫回失敗（例如工作表被保護）**不拋錯**——範本已經推斷出來、模型照樣建得成，
寫不回去只是下次要再推斷一次，改為記一筆 `TEMPLATE_WRITEBACK_FAILED` 警告。

### `CONDITION`

| 語法 | 意思 |
|---|---|
| `ALWAYS` | 一定出現 |
| `NEVER` | 一定不出現 |
| `WEEK_IN:2,4` | 只在 `weekOfMonth` 屬於清單時出現 |
| `IF_FIELD:CHOIR_TITLE` | 只在 `BulletinWeeks` 該欄有值（非空白）時出現 |

### `CONTENT_SOURCE`

| 語法 | 意思 |
|---|---|
| `BLANK` | 內容欄留空 |
| `STATIC` | 用 `CONTENT_VALUE` 原文 |
| `FIELD:SERMON_TITLE` | 取 `BulletinWeeks` 該欄的值 |
| `AUTO:RECITATION` | 見下 |

⚠️ **`ProgramTemplates` 是我們自己的工作表，所以這裡一律嚴格**：認不出的
`CONDITION`／`CONTENT_SOURCE`、`FIELD:`／`IF_FIELD:` 指向不存在的欄位，
全部**直接拋錯**，訊息指明是哪個 `TEMPLATE_ID` 第幾行、值是什麼，並列出
可用欄名。這跟對職事表的寬鬆解析剛好相反——理由見
docs/職事表唯讀介面.md「為什麼對職事表用寬鬆解析」。

### `AUTO:RECITATION`

1. `BulletinWeeks.RECITATION_OVERRIDE` 有值 → 直接用它。
2. 否則按主日日期的**月份**查 Config `RECITATION_MONTH_GROUPS`
   （格式「起月-迄月:Config鍵」，逗號分隔），取該組指定的 Config 鍵的值。

分組與月份邊界**完全由 Config 決定**，程式碼裡沒有 1–4／5–8／9–12 這種
寫死的數字。查不到對應分組時內容留空（不拋錯——誦讀漏填不應該讓整份週報
生不出來）。

### 宣召

「宣召」那一行（`CONTENT_SOURCE` 為 `FIELD:CALL_TEXT`）的內容是
`CALL_TEXT` 與 `CALL_REF` 依 Config `CALL_TO_WORSHIP_FORMAT`
（預設 `{{text}}（{{ref}}）`）合成的：

| 情況 | 結果 |
|---|---|
| 兩者皆有 | 依格式合成 |
| 只有出處 | 只顯示 `（出處）`（2026-04-05 浸禮合堂就是這樣） |
| 只有經文 | 只顯示經文，不留一對空括號 |
| 兩者皆空 | 空字串，並列入待填清單 |

## 待填清單 `missing`

每一項是 `{ field, label, reason }`。掃描以下項目：

- `BulletinWeeks`：`CALL_TEXT`＋`CALL_REF` **兩者皆空**、`SCRIPTURE_REF`、
  `SERMON_TITLE`、`RESPONSE_HYMN`、12 個人數欄、`FLOWER_THIS_WEEK`
- `Announcements`／`Prayers`／`Fellowships` 該日 `ACTIVE=TRUE` 的行數為 0
- 任何 `state === 'PENDING'` 的崗位（`field` 是 `POST:<PostID>`）

⚠️ **`PRELUDE` 留空不算缺**——68 期樣本的序樂全部相同，留空時直接用 Config
`PRELUDE_DEFAULT` 補上即可，不需要每週叫人填一次。

`label` 一律取 `BulletinWeeks` 的中文標題（`COLUMNS.BULLETIN_WEEKS.headers`），
幹事看得懂要去填哪一欄。

## `warnings` 的 code 一覽

除了職事表快照本身的警告（見 docs/職事表唯讀介面.md）之外，本層會加：

| code | 觸發時機 |
|---|---|
| `BULLETIN_WEEK_ROW_NOT_FOUND` | `BulletinWeeks` 沒有該主日那一行，全部人手欄位當空白處理 |
| `NEXT_WEEK_NOT_IN_ROSTER` | 下一個主日不在職事表內，下週事奉留白 |
| `NEXT_WEEK_SNAPSHOT_FAILED` | 讀取下一個主日的快照時拋錯，下週事奉留白 |
| `TEMPLATE_WRITEBACK_FAILED` | 推斷出範本但寫回 `BulletinWeeks` 失敗 |
| `MERGE_GROUP_NOT_FOUND` | `PostDisplay` 指向的合併組在 `MergeGroups` 找不到生效中的定義 |
| `NO_PERSON_DISPLAY` | `PersonID` 在週報的 `PersonDisplay` 找不到生效中的一行 |

## 姓名與尊稱

`resolvePersonDisplay_(personId, nameSnapshot, options)`：

1. `PersonDisplay` 按 `PERSON_ID` 找生效中的一行（`ACTIVE=TRUE`，且目標
   日期在 `EFFECTIVE_FROM`～`EFFECTIVE_TO` 之內，兩欄留空＝不限）。
2. `DISPLAY_OVERRIDE` 有值 → 直接用它，**不加任何尊稱**（覆寫就是完全覆寫）。
3. 否則用職事表的姓名快照，依 `withHonorific` 決定是否接上 `HONORIFIC`。
4. **找不到 `PersonDisplay` 行** → 用原名，並記一筆 `NO_PERSON_DISPLAY`
   警告。⚠️ 不可以靜靜當成「這個人沒有尊稱」——尊稱缺失是要有人補資料的
   問題，不是正常狀態。

⚠️ **職稱類尊稱（`牧師`／`師母`／`傳道`／`宣教士`）無論哪一頁都要顯示**，
只有 `弟兄`／`姊妹` 受 `HONORIFIC_ON_PAGE1`／`HONORIFIC_ON_PAGE3` 控制
（`isTitleHonorific_()`）。理由：核對過印刷版樣本，第 3 頁凡是有牧師／
師母職稱的肢體都完整保留了職稱，只有弟兄姊妹被省略——職稱是那個人的
身分（漏了失禮），弟兄姊妹只是一般敬稱。
