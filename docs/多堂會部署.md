# 多堂會部署（甲：同一份程式碼、多個部署）

2026-11-03（Ivan）：先準備「甲」——同一教會內不同堂會（例如英語堂、華語堂）用同一份程式碼，**每個堂會一個獨立部署**，
資料完全分開。其他教會如果使用，會買斷、全部分開（自己一份 repo、自己的 Google 帳戶），但要預備好方便日後支援和更新。

## 一、每個堂會各自有的東西（完全分開）

| 項目 | 說明 |
|---|---|
| Apps Script 專案 | 綁定各自的週報試算表，各自一個 scriptId（與職事表系統的專案分開）；指令碼屬性、觸發器各自獨立 |
| 週報試算表 | 各自一份（Config、BulletinWeeks、Recipients、EmailTemplates、PostDisplay、ProgramTemplates……） |
| 內容表 | 各自每季一份，放各自的 Shared Drive 資料夾 |
| Word 範本 | 各自四個（平常、浸禮、堂慶、三堂聯合），各自的 logo |
| 輸出資料夾 | Word、master PDF、存檔、內容表、內容表封存，各自的資料夾 |
| Web App | 各自一個部署（各自的 /exec 網址、各自的可用名單） |
| 職事表 | 各自的職事表試算表（Config `ROSTER_SPREADSHEET_ID`），一律唯讀 |

程式碼只有一份（這個 repo）。更新時同一個版本部署到所有堂會（見第四節）。

## 二、堂會專屬的設定清單（Config）

新堂會一定要改／填的鍵（其餘可以先用預設值）：

| 鍵 | 填甚麼 |
|---|---|
| `CONGREGATION_NAME` | 堂會名稱，例如「英語堂」。用在填寫介面標題、電郵 `{{CongregationName}}`、內容表邀請信標題、檔名 `{{CONGREGATION}}` |
| `CHURCH_NAME` | 教會全名（同一教會各堂會相同） |
| `ROSTER_SPREADSHEET_ID`、`ROSTER_WEBAPP_URL` | 這個堂會的職事表（唯讀）與職事表幹事介面網址 |
| `TEMPLATE_FILE_ID_NORMAL`、`_COMBINED_BAPTISM`、`_ANNIVERSARY`、`_COMBINED` | 這個堂會的四個 Word 範本 |
| `YEAR_LOGO_FILE_ID` | 年度 logo（可以留空，用範本內的圖） |
| `BULLETIN_OUTPUT_FOLDER_ID` | Word 輸出資料夾 |
| `PUBLISHED_PDF_FOLDER_ID`、`PUBLISHED_ARCHIVE_FOLDER_ID`、`PUBLISHED_PDF_NAME` | master PDF 與存檔（`PUBLISHED_PDF_FILE_ID` 由選單「建立 master 發佈檔案」自動填） |
| `CONTENT_SHEET_FOLDER_ID`、`CONTENT_SHEET_ARCHIVE_FOLDER_ID`、`CONTENT_SHEET_DOMAIN` | 內容表資料夾與網域 |
| `CONTENT_SHEET_OWNERS`、`CONTENT_SHEET_ADMIN_CONTACT`、`CONTENT_SHEET_DEADLINE_NOTE` | 內容表誰填哪一張、聯絡人、截止 |
| `WEBAPP_ALLOWED_EMAILS`、`WEBAPP_VIEWER_EMAILS`、`PROTECTION_EDITOR_EMAILS` | 這個堂會可以用填寫介面的人 |
| `WEBAPP_URL`、`PREVIEW_WEBAPP_URL` | 這個部署的 Web App 網址（部署之後填） |
| `EMAIL_ALLOWLIST` | 測試期間只寄給這幾個地址；正式使用時留空 |
| `OUTPUT_FILE_NAME_PATTERN` | 新部署預設已是 `{{SERVICE_DATE}}_{{CONGREGATION}}週報.docx`，不用改 |
| `CANTONESE_SUBCOLUMN_LABEL`、`ATTENDANCE_COMBINED_COLUMN_LABEL` | 人數表欄名（見第五節） |
| `FINANCE_TITLE_PATTERN` 等財政報告字眼 | 財政報告由哪一個堂會印就照那一個堂會的字眼 |
| `DRY_RUN`、`WEBAPP_SIMULATED_TODAY` | 建立時 `DRY_RUN=TRUE`；上線前清空 `WEBAPP_SIMULATED_TODAY` |

工作表（各自一份，按「初始化工作表」建好之後填）：Recipients（收件人與組別）、EmailTemplates（電郵範本；新部署的種子已用
`{{CongregationName}}`）、PostDisplay（崗位顯示）、ProgramTemplates（程序範本）、PersonDisplay（尊稱）、Fellowships 常設時間表等。

## 三、新堂會的建立步驟

1. **Shared Drive 資料夾**：建一個這個堂會的資料夾，裏面再建「Word 輸出」「發佈」「發佈存檔」「內容表」「內容表封存」「範本」。
2. **Word 範本**：把粵語堂四個範本複製到「範本」資料夾，按這個堂會的印刷版改（字眼、logo）；用「管理版本 ▸ 上載新版本」更新，不要轉成 Google 文件。
3. **週報試算表**：在這個堂會的資料夾建一份新的 Google 試算表（名稱例如「Bulletin Automation 英語堂週報系統」）。
4. **Apps Script 專案**：在那一份試算表按「擴充功能 ▸ Apps Script」建立（綁定這一份試算表，與粵語堂部署同一做法；
   程式用 `SpreadsheetApp.getActiveSpreadsheet()` 讀自己的試算表）。專案設定 ▸ 指令碼 ID＝scriptId。
   它與職事表系統的 Apps Script 專案是分開的（不可以寫入職事表的專案）。
5. **第一個部署 ID**：在編輯器「部署 ▸ 新增部署作業 ▸ 網頁應用程式」（以本人身分執行、網域內使用者可以存取）建一個，記下部署 ID（AKfy…）。
6. **推送程式碼**：在 repo 根目錄的 `deploy-targets.txt`（照 `deploy-targets.example.txt`）加一行 `english <scriptId> <部署 ID>`，
   然後執行 `deploy_multi.bat "第一次部署"`。
7. **初始化**：打開試算表，選單「週報系統 ▸ 初始化工作表」，再按「檢查授權範圍」完成授權。
8. **填 Config**：照第二節逐項填；填好之後按「設定差異檢查（唯讀）」，核對「與預設值不同」那一段只有應該不同的鍵。
9. **建立 master 發佈檔案**（選單），**建立本季空白週報**、**建立本季內容表**。
10. **測試**：`DRY_RUN=TRUE`、`EMAIL_ALLOWLIST` 只填自己，打開填寫介面試一期，產生 Word 核對版面。
11. **觸發器**：選單「安裝自動寄送觸發器」（每個部署各自安裝；見交接文件的觸發器清單）。
12. **上線**：清空 `WEBAPP_SIMULATED_TODAY`、`EMAIL_ALLOWLIST`，`DRY_RUN` 改 FALSE（決定時間的人決定）。

## 四、更新（同一個版本部署到所有堂會）

- 粵語堂照舊用 `deploy.bat`（會 git commit／push 與部署）。
- 其他堂會：`deploy_multi.bat "說明"`，逐個 `deploy-targets.txt` 內的堂會做 `clasp push --force` 與 `clasp deploy`
  （每個堂會在 `deploy-targets\<名稱>\.clasp.json`，根目錄的 `.clasp.json` 不會被改）。任何一個失敗就停，講明是哪一個。
  ⚠️ 2026-11-03 寫好，未在真實的第二個專案試過；第一次用時留意 `clasp push` 是不是推了 `src/` 的全部檔案。
- 每個堂會部署之後：按「初始化工作表」（有新 Config 鍵或欄時）；按「設定差異檢查」看有沒有「缺少的設定」。
- 版本號：`src/Constants.gs` 的 `APP_VERSION`（＝部署日期），「關於本系統」、填寫介面頁底、設定差異檢查都顯示；
  改了甚麼、部署之後要做甚麼寫在 `docs/更新說明.md`（最上面一段＝現在的版本）。

## 五、仍然寫在程式碼內的字（屬全教會，同一教會各堂會相同）

以下是同一教會內各堂會共用的字，所以「甲」不用改；**其他教會使用之前要改成 Config**（記入待辦）：

- 人數表四個單位：英語堂、粵語堂（東區／主堂、北岸）、華語堂（`src/ContentSheet.gs` 內容表「崇拜人數」欄名、
  `src/BulletinModel.gs` `buildAttendanceTable_()`、`src/Constants.gs` 欄位中文名、填寫介面人數表表頭）。
- 「三堂聯合崇拜」等合堂字眼（範本名稱、說明文字；印在週報上的字在 Word 範本內，各自可以改）。
- 工作表欄的中文標題（例如 BulletinWeeks「英語堂崇拜」）——只是工作表上的標題，不印在週報。
- 說明文字裏提到的「粵語堂職事表」（Config 說明欄、選單「關於本系統」）。

## 六、其他教會（買斷、全部分開）

- 各自一份 repo（由這個 repo 複製），各自的 Google 帳戶、Shared Drive、職事表。
- 支援：請對方先講版本號（「關於本系統」）與「設定差異檢查」報告的「設定匯出」一段（電郵、ID 已遮蔽），就知道對方用哪一個版本、改過甚麼設定。
- 更新：對方由自己的版本號起，逐段看 `docs/更新說明.md`，照「部署之後要做」做；程式碼用 git 合併這個 repo 的新版本。
- 賣出之前要做：第五節的字改成 Config；Config 說明欄裏提到本堂的例子改為一般例子。
