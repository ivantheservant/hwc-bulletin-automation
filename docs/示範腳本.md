# 示範腳本

一份可以**照住做**的腳本，同時是向堂委會、執事會簡報的流程。

每一步都寫明四件事：

| | 意思 |
|---|---|
| **誰做** | 幹事／堂委／執事／系統自動 |
| **去邊度** | 開哪一個畫面、撳哪一個選單 |
| **預期見到** | 做對了會見到什麼 |
| **失敗時點算** | 見不到預期的東西，下一步做什麼 |

⚠️ **示範之前先做的三件事**（幹事，5 分鐘）：

1. 撳選單 **`週報系統 ▸ 上線前檢查（唯讀）`**——八項全部 🟢 或者只有可以
   接受的 🟡 才開始示範。有 🔴 就先處理，不要當住人前撞。
2. 確認 Config 的 `DRY_RUN`：**示範時應該是 `TRUE`**（測試模式，不會真的
   寄信給全教會）。示範完畢正式上線才改 `FALSE`。
3. 準備好職事表那一季的資料。沒有也不要緊——第 2 步就是示範「職事表未有
   資料照樣做得落去」。

## 第一部分　由零開始建立新一季

**誰做：幹事　　需時：約 20 分鐘**

⚠️ **由 R-038 起，這一部分全部可以喺填寫介面做完，唔使開試算表。**
填寫介面捲到「發佈及匯出」上面，有一個摺疊住的
**「季度作業（<季度>）」**，撳標題展開就見到八粒按鈕。

示範時建議**用填寫介面**——幹事日常見到嘅就係嗰個畫面。下面每一步仍然
寫住選單那一條路（維護同災難復原時用），兩邊做嘅係同一件事。

| 填寫介面「季度作業」 | 等同選單 |
|---|---|
| 建立本季週報 | `週報系統 ▸ 建立本季空白週報` |
| 建立／刷新本季內容表 | `內容表 ▸ 建立本季內容表` |
| 寄出內容表連結 | `內容表 ▸ 寄出內容表連結` |
| 從內容表匯入（整季） | `內容表 ▸ 從內容表匯入` |
| 本季待填清單／檢查職事表分歧／上線前檢查／發佈版本記錄 | 同名選單項目 |

⚠️ 介面那邊每一粒**都會先彈預覽講明將會發生咩事**，確認之後先至真做。
選單那邊三粒（建立週報、建立內容表、寄連結）係做完先講——呢個分別
值得喺示範時講一講，因為堂委會問「撳錯咗點算」。

### 1. 建立本季週報（由職事表抓事奉資料）

| | |
|---|---|
| 去邊度 | 週報試算表 ▸ 選單 `週報系統 ▸ 建立本季空白週報` |
| 撳咩 | 輸入季度 ID（例如 `2027T4`）→ 確定 |
| 預期見到 | 對話框：「季度 2027T4：新增 13 行，略過 0 行」。`BulletinWeeks` 多了 13 行，每一行的日期、週次、程序範本都填好了 |
| 失敗時點算 | 對話框話「職事表未有資料」→ **不是錯誤**，見第 2 步。<br>對話框話「季度 ID 格式不正確」→ 格式是 `YYYYTn`，例如 `2027T4`，不是 `2027Q4`。 |

⚠️ 講解重點：**這一步不會覆寫任何已經填好的東西。** 已經存在的主日會被
「略過」，所以撳幾多次都安全。

### 2. 若職事表未有該季 → 照樣建立，事奉欄位留空，之後補抓

| | |
|---|---|
| 去邊度 | 同上 |
| 預期見到 | 對話框：「本季職事表未有資料，已建立 13 個主日，事奉欄位全部留空。」`BulletinWeeks` 的「職事表狀態」欄全部是 `NOT_FOUND` |
| 之後點算 | 職事表準備好之後，撳選單 `週報系統 ▸ 補抓空白的事奉欄位（整季，不覆寫已填的）` |
| 失敗時點算 | 補抓之後仍然話「找不到」→ 確認 Config 的 `ROSTER_SPREADSHEET_ID` 對不對，以及職事表那一季真的已經生成。 |

⚠️ 講解重點（**這一點值得花時間講**）：

> 職事表未出**不是錯誤，是「未到時候」**。
> 系統照樣讓你先填講題、經文、詩歌、家事報告——那些本來就與事奉無關。
> 事奉欄位留空，職事表出咗之後撳一下補抓就填返。
>
> 補抓**只填空白格**，你自己填過的一格都不會被覆寫，所以撳幾多次都一樣。

### 3. 建立本季內容表

| | |
|---|---|
| 去邊度 | 選單 `週報系統 ▸ 內容表 ▸ 建立本季內容表` |
| 撳咩 | 輸入季度 ID → 確定 |
| 預期見到 | 對話框列出七張分頁（`_說明`、家事報告、代禱事項、團契聚會、財政報告、崇拜人數、宣召），並附一條 Google 試算表連結 |
| 失敗時點算 | 話「尚未設定內容表資料夾」→ 在 Config 填 `CONTENT_SHEET_FOLDER_ID`（Shared Drive 內一個資料夾的 ID）。 |

⚠️ 講解重點：**已經有就不會重建。** 第二次撳只會補分頁、補下拉選單，
回報「已更新，未重建」——堂委已經填好的東西不會不見。

### 4. 寄內容表連結給堂委與執事

| | |
|---|---|
| 去邊度 | 選單 `週報系統 ▸ 內容表 ▸ 寄出內容表連結` |
| 撳咩 | 輸入季度 ID → 確定 |
| 預期見到 | 對話框回報寄給了幾多人。`SendLog` 多了對應行數，`STATUS` 是 `CONTENT_SHEET_INVITE` |
| 失敗時點算 | `DRY_RUN=TRUE` 時**不會真的寄出**，但 `SendLog` 照樣有紀錄——這是預期行為，示範時正好用來講解。<br>話「沒有收件人」→ 在 `Recipients` 加人，並確認 `GROUP_NAME` 與 Config 的 `CONTENT_SHEET_INVITE_GROUPS` 對得上。 |

## 第二部分　堂委與執事填內容

**誰做：堂委、執事　　需時：約一星期**

### 5. 開內容表，填六類內容

| | |
|---|---|
| 去邊度 | 電郵裏面那條 Google 試算表連結 |
| 撳咩 | 逐張分頁填：家事報告、代禱事項、團契聚會、財政報告、崇拜人數、宣召 |
| 預期見到 | 「主日日期」是一個下拉選單，只列得出本季的主日；填錯日期會被拒絕 |
| 失敗時點算 | 下拉選單是空的 → 那一季的主日清單未建立，回去做第 1 步。 |

⚠️ 講解重點：

- **不刪行，只把「有效」改 `FALSE`。** 要取消一條報告，改「有效」就得，
  不要刪行——刪咗就查不到當初填過什麼。
- 「次序」用 10、20、30 這樣跳號，方便日後在中間插入。

### 6. 示範「連續到」：一條報告連登三個星期只需填一次

| | |
|---|---|
| 去邊度 | 內容表 ▸ `家事報告` 分頁 |
| 撳咩 | 「主日日期」揀第一次出現那個主日；「連續到」揀最後一次出現那個主日 |
| 預期見到 | 匯入之後，那一條報告會在中間每一個主日都出現 |
| 失敗時點算 | 只出現一次 → 檢查「連續到」是不是留空了（留空＝只出現一週）。 |

⚠️ 講解重點：實際週報有大量連續三、四週的報告，這一欄是整張表最重要的
設計——**填一次，之後幾個星期自動有**。

## 第三部分　每星期的例行工作

**誰做：幹事　　需時：約 10 分鐘**

### 7. 從內容表匯入

| | |
|---|---|
| 去邊度 | 選單 `週報系統 ▸ 從內容表匯入` |
| 撳咩 | 輸入季度 ID → **先看差異** → 確認才寫入 |
| 預期見到 | 先出一個對話框：「新增 N、修改 N、刪除 N、不變 N」＋ 前 20 行明細。確認之後才真的寫 |
| 失敗時點算 | 四個數字全部 0 → 睇差異對話框那句「主日清單來源」。如果是「取不到」，代表季度 ID 打錯了。 |

⚠️ 講解重點：**先看差異，確認才寫入。** 系統不會靜靜改你的資料。

### 8. 在填寫介面補填講員、講題、讀經

| | |
|---|---|
| 去邊度 | 填寫介面（Web App 網址） |
| 撳咩 | 上面兩個下拉揀季度與主日 → 填「講題」「經文」「回應詩」等 → 撳「儲存」 |
| 預期見到 | 主日下拉每一項後面有狀態：`已發佈 第 N 版`／`待填 N 項`／`已齊`。頂部有「待填 N 項」「警告 N 項」「衝突 N 項」三個數字 |
| 失敗時點算 | 見到「沒有使用權限」→ 睇那一頁印出的「你目前登入的是：xxx」，多數是瀏覽器登入了個人 Gmail 而不是教會帳戶。<br>季度下拉是空的 → 睇旁邊那句提示，多數是全部季度都封存咗，勾「顯示已封存」就見得返。 |

⚠️ 講解重點：

- 七個唯讀區塊（家事報告、代禱、團契、財政、人數、宣召出處、宣召經文）
  **來自內容表**，在這裏改不到——要改就去內容表改，再匯入一次。
- 「重讀職事表（本主日，不覆寫）」：只重新讀這一個主日的職事表，
  **不會動你正在填的欄位**。

### 9. 產生 Word

| | |
|---|---|
| 去邊度 | 選單 `週報系統 ▸ 產生本週週報（Word）` |
| 撳咩 | 輸入主日日期 → 確定 |
| 預期見到 | 對話框：「殘留佔位符：0 個」＋ 替換數、內容份量估算、檔案連結 |
| 失敗時點算 | 標題變成「⚠️ 已產生週報，但產出有問題」→ 睇內文：<br>• 殘留佔位符 > 0：範本那一段被 Word 切斷了，要重打<br>• 偵測到重複段落：**多數是複製漏刪**，用 Word 開啟核對 |

⚠️ 講解重點（**這一點值得花時間講**）：

> 系統會回頭**實掃產出的檔案**，確認紙上真的沒有 `{{` 開頭的文字，
> 亦會偵測有沒有段落重複出現。
>
> 88 期真實週報之中，有三期的第 5、6 頁其實是編輯時複製漏刪，
> **一直沒有人發現**。現在系統會直接指出來。

### 10. 用 Word 開啟核對版面，另存為 PDF

| | |
|---|---|
| 去邊度 | 對話框那條連結 → 下載 → 用 Word 開啟 |
| 撳咩 | 核對版面與頁數 → 另存為 PDF |
| 預期見到 | 4 頁（或者內容多時 5 頁） |
| 失敗時點算 | 頁數多過預期 → 回去睇第 9 步的「內容份量估算」與「重複段落」兩項提示。 |

⚠️ 講解重點：**頁數要靠 Word 排版引擎，系統算不到。** 系統給的是估算，
最後一定要人手用 Word 開一次。

### 11. 發佈到 master 連結

| | |
|---|---|
| 去邊度 | 填寫介面 ▸ 「發佈及匯出」區塊 |
| 撳咩 | 勾「發佈到 master 連結」→ 選剛才另存那個 PDF → 撳「執行」 |
| 預期見到 | 版本 +1，`PublishLog` 多一行，頂部狀態列更新 |
| 失敗時點算 | 話「你選的是目前已發佈的那一份」→ **揀錯檔案了**，要揀 Word 新另存那一個，不是下載回來的舊 PDF。<br>話「在 30 秒內重複發佈」→ 撳多了一次，系統已經擋住，版本號沒有變。 |

⚠️ 講解重點：**教會網站那條連結永遠不變。** 系統是原地覆寫同一個檔案，
所以網站那邊一次過設定好就不用再改。

### 12. 寄出通知

| | |
|---|---|
| 去邊度 | 同一個區塊 |
| 撳咩 | 勾「寄出」→ 撳「執行」 |
| 預期見到 | 對話框回報收件人數；`SendLog` 多了對應行數 |
| 失敗時點算 | `DRY_RUN=TRUE` 時不會真寄，但 `SendLog` 照樣有紀錄。正式上線記得改 `FALSE`。 |

## 第四部分　自動發生的事

**誰做：系統自動（不用人手）**

### 13. 每星期一自動寄預覽連結給堂委、執事、幹事

| | |
|---|---|
| 幾時 | 每星期一（Config `SEND_WEEKDAY`／`SEND_HOUR`） |
| 做咩 | 寄一封信，內含**固定不變**的草稿預覽連結 |
| 預期見到 | `SendLog` 多幾行 `STATUS='PREVIEW'`。收件人開連結就見到下一個主日目前為止的內容 |
| 失敗時點算 | 沒有寄 → 睇 `ErrorLog`。最常見是 Config 的 `PREVIEW_WEBAPP_URL` 未填。 |

⚠️ 講解重點：

> 那條連結**固定不變**，貼一次入群組就得，之後每星期打開都是最新一期。
>
> 預覽頁是**純 HTML**，版面與正式印刷版不同——它的用途是核對**內容**，
> 不是看版面。未填的欄位會顯示灰色的「（未填）」，一眼看得出仲欠咩。

### 14. 夏令時間轉換前一週，家事報告自動加入提示

| | |
|---|---|
| 幾時 | 建立或刷新內容表時自動計算 |
| 做咩 | 9 月最後一個主日開始、4 月第一個主日完結，提示登在**改動當日的前一個主日**那一期 |
| 預期見到 | 內容表 `家事報告` 自動多一行，「來源」欄是 `SYSTEM_DST` |
| 失敗時點算 | 沒有自動加 → 那一季可能根本不含提示日（`YYYYT2` 與 `YYYYT4` 永遠不會含）。 |

⚠️ 講解重點：**由日期計算，沒有寫死日期表**，2030 年都仍然啱。
你改咗那一行的內容之後，系統就**永遠不再覆寫它**。

### 15. 誦讀按四個月自動輪替

| | |
|---|---|
| 幾時 | 每次組週報時自動計算 |
| 做咩 | 按四個月一個循環決定用哪一段誦讀 |
| 預期見到 | 填寫介面的「誦讀」欄顯示「（留空＝自動）」，實際輸出見程序預覽 |
| 失敗時點算 | 要覆寫某一週 → 在填寫介面的「誦讀（覆寫）」填指定值。 |

## 第五部分　出事時怎樣救

**誰做：幹事（必要時找 IT）**

### 16. 發佈錯了 → 選單「發佈版本記錄」→ Drive 還原

| | |
|---|---|
| 去邊度 | 選單 `週報系統 ▸ 測試工具 ▸ 發佈版本記錄（唯讀）` |
| 預期見到 | `Diagnostics` 列出 master 檔案的每一個 Drive 版本（時間、大小、修改者），並寫明還原步驟 |
| 點救 | 在 Drive 開啟那個 PDF ▸ 檔案 ▸ 版本記錄 ▸ 揀回上一個版本 ▸ 還原 |

⚠️ 講解重點：**檔案 ID 不變，所以還原之後網站那條連結照樣有效。**

### 17. 匯入錯了 → 內容表改正 → 重新匯入（先看差異）

| | |
|---|---|
| 去邊度 | 內容表改正 → 選單 `從內容表匯入` |
| 預期見到 | 差異對話框會顯示「修改 N」，確認之後才寫入 |
| 點救 | 匯入是**冪等**的：改正之後再匯入一次就得，不會愈匯愈亂。 |

⚠️ 如果整季都亂了：選單 `週報系統 ▸ 還原季度備份`——每次大動作之前系統
都會自動備份一次。

### 18. 職事表改了 → 補抓空白的事奉欄位（不覆寫已填的）

| | |
|---|---|
| 去邊度 | 選單 `週報系統 ▸ 補抓空白的事奉欄位（整季，不覆寫已填的）` |
| 預期見到 | 對話框回報：補了幾多格、仍有幾多格空白、職事表狀態由什麼變什麼 |
| 點救 | 撳幾多次都安全——它只填空白格。 |

⚠️ 如果職事表**改了一個已經填好的人名**：那一格不會被補抓覆寫（系統沒有
資格改你填過的東西）。想知道兩邊有沒有分歧，睇填寫介面頂部的
「衝突 N 項」，或者撳選單 `檢查職事表分歧`。

## 附錄　常用選單一覽

⚠️ **R-038 之後，下面每一項喺填寫介面「季度作業」區塊都有一粒對應嘅
按鈕**，而且介面嗰邊會先出預覽。呢個表兩邊通用。

| 選單 | 做咩 | 會不會覆寫人手資料 |
|---|---|---|
| 建立本季空白週報 | 為該季每一個主日建一行骨架 | **不會**（已存在的略過） |
| 補抓空白的事奉欄位（整季，不覆寫已填的） | 用職事表補回空白的事奉格 | **不會**（只填空白格） |
| 內容表 ▸ 建立本季內容表 | 建立／刷新內容表七張分頁 | **不會**（已有就只補結構） |
| 從內容表匯入 | 把內容表寫入週報 | **會**，但先出差異對話框要你確認 |
| 立即整理舊季度（封存，不刪資料） | 把舊季度標記為已封存 | **不會刪任何資料**，只是預設不顯示 |
| 取消封存季度（完全還原） | 把已封存的季度還原 | **不會**（完全還原） |
