對應需求 R-001 至 R-015。

## 第一部分：發佈及匯出

### 1.1 master 連結怎樣做到「永遠不變」

在 Shared Drive 放**一個固定的 PDF 檔案**，權限設為「知道連結的人可檢視」。
每次發佈時**覆寫這個檔案的內容**，不是刪除再上載——檔案 ID 不變，連結不變。
Drive 自己會保留版本記錄，可以回溯。

Config 新增：

| 鍵 | 說明 |
|---|---|
| `PUBLISHED_PDF_FILE_ID` | master 檔案 ID（建立一次，之後不要改） |
| `PUBLISHED_PDF_NAME` | 檔案顯示名稱，預設 `粵語堂週報（最新一期）.pdf` |
| `PUBLISHED_ARCHIVE_FOLDER_ID` | 存檔資料夾，每次發佈額外存一份帶日期的副本 |

給你的三條連結（放上教會網站用）：

- **檢視**：`https://drive.google.com/file/d/<ID>/view` — 一般會眾用這條
- **內嵌**：`https://drive.google.com/file/d/<ID>/preview` — 想直接嵌在網頁裏用這條
- **下載**：`https://drive.google.com/uc?export=download&id=<ID>`

### 1.2 PDF 從哪裏來（重要限制）

Apps Script 無法把 `.docx` 轉成忠於原版的 PDF。唯一途徑是轉成 Google 文件再匯出，
而 A5 版面、文字方塊、圓角框、MYuenHK-Light 與 CXingKaiHK-Bold 都會走樣。
會眾看的就是這份 PDF，不能走樣。

**所以流程是：**

```
1. 系統產生 .docx
2. 幹事撳「下載 Word」
3. 用 Word 開，最後核對一次，另存為 PDF
4. 回到 UI 撳「上載 PDF 並發佈」，選那個 PDF
5. 之後全部自動：覆寫 master 檔案 → 存檔副本 → （如有勾選）寄出
```

第 3 步是唯一不能自動化的一步。好處是多了一道人手覆核，發佈出去的東西一定有人看過。

### 1.3 UI 版面

**頂部狀態列**（R-008，常駐）

```
目前已發佈：2027-11-07（第 3 版）　2026-08-22 10:04 由 ivan 發佈　[開啟]
```

未發佈過就顯示「尚未發佈過任何一期」。資料來自新的 `PublishLog` 工作表。

**「發佈及匯出」區塊**

```
┌ 發佈及匯出 ─────────────────────────────────┐
│ 主日：2027-11-07                              │
│                                               │
│ [下載 Word]  [下載 PDF]                       │
│                                               │
│ ☑ 發佈到 master 連結（需上載 PDF）            │
│    [選擇 PDF 檔案…]  未選擇                   │
│                                               │
│ ☑ 寄出                                        │
│    ☐ IT   ☑ CC 堂委   ☑ DB 執事   ☑ 我自己    │
│    自訂電郵：[________________]（逗號分隔）   │
│                                               │
│ ⚠ 模擬模式開啟中，寄出只會記錄，不會真的寄出  │
│                                               │
│              [執行]                           │
└───────────────────────────────────────────────┘
```

- 兩個勾選各自獨立（R-003）：只勾發佈、只勾寄出、兩個都勾，三種都可以
- 「下載 PDF」是把 master 檔案下載，不是即時轉檔——按鈕文字要寫清楚
- `DRY_RUN` 為 `TRUE` 時，橙色橫幅一定顯示

### 1.4 發佈前的檢查（R-006、R-007）

撳「執行」之後，先出一個確認視窗，列出全部問題，然後才可以繼續：

```
發佈前檢查：2027-11-07

未填欄位（12 項）
  程序：講員、講題、讀經經文
  人數：英語堂崇拜、粵語堂北岸崇拜 …（逐項列出，不截斷）
  家事報告：0 條
  代禱事項：0 條

日期提醒
  ⚠ 這一期不是下一個主日（下一個是 2026-08-23）
  ⚠ 2026-08-23 至 2027-10-31 之間有 62 個主日未發佈

  ☐ 我明白以上情況，仍然要發佈（未填的欄位會留空）

        [取消]        [確認發佈]
```

- 未填欄位**全部列出**，不設上限、不寫「等 N 項」
- 三種日期異常各自一句：過去日期／不是下一個主日／中間跳過了 N 個主日
- 勾了那個方框才能撳「確認發佈」；勾選這件事本身要記入 `PublishLog`

### 1.5 `PublishLog` 工作表

| 中文標題 | 機器鍵 |
|---|---|
| 主日日期 | `SERVICE_DATE` |
| 版本 | `VERSION_NO` |
| 發佈時間 | `PUBLISHED_AT` |
| 發佈人 | `PUBLISHED_BY` |
| 存檔檔案 ID | `ARCHIVE_FILE_ID` |
| 是否有寄出 | `SENT` |
| 收件組別 | `SENT_GROUPS` |
| 未填欄位數 | `MISSING_COUNT` |
| 是否強制發佈 | `FORCED` |
| 強制原因 | `FORCED_REASON` |

同一個主日再發佈一次，`VERSION_NO` 加一。頂部狀態列顯示最新一行。

## 第二部分：內容表

### 2.1 為什麼要獨立一個檔案

七項內容的填寫人是堂委與執事，不是幹事一個人。把他們放進週報試算表，
即使有工作表保護，仍然有機會誤觸系統表。獨立一個檔案，權限乾淨，
連結可以放心寄出去。

**一季一個檔案**（R-013），放 Shared Drive，命名 `週報內容_2027T4`。
季度結束就是天然的封存，不會愈積愈多。

### 2.2 唯一編輯來源的規則（避免兩個真相來源）

- **內容表是唯一編輯來源。** 週報試算表內的 `Announcements`、`Prayers`、
  `Fellowships`、`Finance` 等表，變成匯入後的快照
- 匯入是**單向**：內容表 → 週報試算表。週報這邊不會回寫內容表
- 有人在週報這邊手改了快照，下一次匯入會被覆寫，並在 `AuditLog` 留下記錄
- UI 那七個區塊改為唯讀，上方一行說明：
  `本區內容來自內容表，最後匯入：2026-08-22 10:04　[開啟內容表]　[重新匯入]`

### 2.3 內容表的工作表與版面

沿用現有慣例：第 1 行中文標題、第 2 行機器鍵、第 3 行起是資料。
凍結首兩行。灰底＝系統填，白底＝人手填。日期一律用下拉選單（只能揀該季的主日），
避免打錯格式。

**`_說明`**（第一張，開檔就見到）
誰負責哪一張表、幾時要填好、一個填寫範例、幹事的聯絡方法。

**`家事報告`**

| 主日日期 | 排序 | 內容 | 連續到（可留空） | 生效 |
|---|---|---|---|---|
| 2027-11-07 | 1 | 熱烈歡迎來賓… | | TRUE |
| 2027-11-07 | 2 | 12 月主日學報名… | 2027-11-28 | TRUE |

- 一個主日可以有多行，用「排序」決定先後（R-014）
- **「連續到」是關鍵**：一條要連續登幾個星期的報告，只需輸入一次，
  填上結束的主日，中間幾期自動出現，不用逐週重抄
- 不刪行，只把「生效」改 `FALSE`

**`代禱事項`** — 欄位與家事報告完全一樣（包括「連續到」）

**`團契聚會`**

| 主日日期 | 排序 | 團契 | 日期 | 時間 | 週會內容 | 生效 |
|---|---|---|---|---|---|---|

四欄全部是文字，不做日期或時間格式轉換。

**`財政報告`**（按月，不是按週）

| 月份 | 排序 | 類型 | 項目 | 本月實際 | 截至本月實際 | 截至本月預算 | 全年預算 | 生效 |
|---|---|---|---|---|---|---|---|---|
| 2027-09 | 1 | 明細 | 奉獻收入 | 42,150 | 380,220 | 375,000 | 500,000 | TRUE |
| 2027-09 | 90 | 附註 | 上列數字未經核數 | | | | | TRUE |
| 2027-09 | 99 | 結餘 | 本月結餘 12,300 | | | | | TRUE |

「類型」三選一：明細／附註／結餘。系統按這一欄決定放進表格、放進附註行、
還是放進結餘行。週報顯示哪一個月，仍然由現有的「該主日的上一個月」規則決定。

**`崇拜人數`**（按崇拜日期，不是週報日期）

| 崇拜日期 | 英語堂崇拜 | 粵語堂東區崇拜 | 粵語堂北岸崇拜 | 華語堂崇拜 | 英語堂祈禱會 | …（共 12 欄） | 生效 |

系統自己找「該週報日期減七天」那一行，不用人手對。
12 格一律文字，容許 `--`、`前:5 / 後:120` 這類寫法。

**`宣召`**

| 主日日期 | 宣召出處 | 宣召經文 | 生效 |
|---|---|---|---|

### 2.4 建立、寄連結、匯入

**選單「建立本季內容表」**
1. 問季度（預設用 `resolveWorkingQuarter_()`）
2. 在 Shared Drive 建檔、建六張表加 `_說明`、寫入該季全部主日、設好下拉選單
3. 檔案 ID、連結寫入新的 `ContentSheets` 工作表
4. 冪等：已存在就不重建，只補缺少的欄位與新增的主日

**選單「寄出內容表連結」**（R-015）
- 收件人：Config `CONTENT_SHEET_INVITE_GROUPS`，預設 `CC,DB,ADMIN`
- 信件內容：內容表連結、該季主日清單、截止日期、誰負責哪一張表
- 範本放 `EmailTemplates`，受 `DRY_RUN` 保護，寫 `SendLog`
- Config `CONTENT_SHEET_INVITE_LEAD_DAYS`（預設 21）：新季度出現時提前幾多日自動寄
- 沿用現有「自動提示下一季」的機制，同一季只寄一次

**選單／UI 按鈕「從內容表匯入」**（R-012）
1. 兩個選項：整季匯入 ／ 只匯入這一個主日
2. 先算差異，顯示：新增 N 行、修改 N 行、刪除 N 行，並列出前 20 行明細
3. 確認之後才寫，逐格記 `AuditLog`，來源標 `CONTENT_SHEET`
4. 「連續到」的範圍在匯入時展開成逐個主日的行

**`ContentSheets` 工作表**

| 季度 | 檔案 ID | 連結 | 建立時間 | 最後匯入時間 | 邀請寄出時間 |
|---|---|---|---|---|---|

## 第三部分：實作次序

分三個 prompt，不要一次過做完：

1. **內容表**（R-010、R-013、R-014、R-015）：建立、寄連結、`ContentSheets`
2. **匯入與 UI 唯讀化**（R-011、R-012）：差異預覽、匯入、七個區塊改唯讀
3. **發佈及匯出**（R-001 至 R-009）：`PublishLog`、上載 PDF、覆寫 master、
   發佈前檢查、寄出、頂部狀態列

先做內容表，因為發佈前檢查要靠它才有完整的「未填欄位」清單。
