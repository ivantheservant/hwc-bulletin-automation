# 移交清單

Ivan 目前是本系統試算表、Apps Script 專案、GitHub repo 的擁有者。
如果日後要把系統交給教會的幹事角色帳戶（而不是 Ivan 個人帳戶）長期
維運，逐項照下面清單處理，避免交接後系統忽然停擺（最常見的死因是
「擁有者帳戶被停用，觸發器跟著全部失效」）。

⚠️ 移交前後都要用「完成度自我檢測」（見
[幹事操作說明.md](幹事操作說明.md)）跑一次，確認移交過程沒有弄壞任何
一項。

---

## 1. 試算表擁有權

1. 把「週報系統」試算表的擁有權**轉移**給幹事角色帳戶（Google Sheets
   ▸ 共用 ▸ 進階 ▸ 轉移擁有權）。轉移之後 Ivan 的權限會自動降為
   編輯者。
2. 確認幹事角色帳戶對「粵語堂職事表」試算表至少有**檢視**權限——本
   系統對職事表全程唯讀，不需要編輯權限，但完全沒有權限的話連讀取
   都會失敗。

---

## 2. Apps Script 專案擁有權

1. Apps Script 綁定在試算表上，轉移試算表擁有權**不會**自動轉移
   Apps Script 專案本身的擁有權（兩者是分開的）。
2. 在 Apps Script 編輯器（Extensions ▸ Apps Script）確認新擁有者對
   專案有**編輯**權限，方便日後改程式；如果需要新擁有者能夠獨立
   部署 Web App、安裝觸發器，也要確認對方有這個權限。
3. **新帳戶第一次用這個專案，一定要重新走一次授權畫面**——授權是
   綁在帳戶上的，轉移擁有權不會連帶轉移授權。用新帳戶登入試算表，
   撳選單「檢查授權範圍」，照對話框指引完成授權；詳見
   [上線前檢查清單.md](上線前檢查清單.md)「第 0 步：確認授權範圍」。
3. 如果之後改由幹事角色帳戶自己維護程式碼，考慮由那個帳戶重新從
   GitHub repo `clasp push` 一次，確保部署身分跟擁有者一致。

---

## 3. 觸發器重裝

**觸發器是綁定在「執行身分」（安裝觸發器的那個帳戶）上的**，轉移
擁有權不會自動把觸發器轉給新帳戶。移交後：

1. 用新的幹事角色帳戶登入試算表；
2. 撳「查看觸發器狀態」確認現況；
3. 逐一撳「安裝自動寄送觸發器」「季度填寫表 ▸ 安裝填寫表同步觸發器」
   「季度填寫表 ▸ 安裝填寫表對帳觸發器」，用新帳戶重新安裝一次
   （每個安裝函式都會先移除舊的同名觸發器，不會裝出重複）；
4. Ivan 原本帳戶安裝的舊觸發器，如果沒有被上面第 3 步的「先移除」
   邏輯清掉（例如是用不同帳戶身分裝的），要手動到 Apps Script
   編輯器的「觸發器」頁面確認清乾淨，避免同一件事被觸發兩次。

---

## 4. Web App 重新部署

1. Web App（填寫介面）的部署身分同樣綁定在部署當下的帳戶。轉移
   擁有權之後，用新的幹事角色帳戶在 Apps Script 編輯器**重新部署**
   一次（Deploy ▸ Manage deployments ▸ 建立新版本，或視需要建立新的
   部署）。
2. 重新部署之後網址通常會變（除非是「更新現有部署」而不是「建立新
   部署」）——記得把新網址填回 `Config` 的 `WEBAPP_URL`，否則「開啟
   填寫介面」選單與季度填寫邀請信裡的連結都會指向舊網址。
3. 部署設定要確認「執行身分」是新的擁有者帳戶、「存取權限」符合
   實際需要（例如「教會內任何人」或指定的網域）。
4. 部署完成後用「開啟填寫介面」實際打開一次，確認能正常載入、能
   儲存。

---

## 5. Drive 資料夾權限

1. `Config` 的 `BULLETIN_OUTPUT_FOLDER_ID` 指向的雲端硬碟資料夾（週報
   Word 檔輸出處）——確認新擁有者帳戶對這個資料夾有**編輯**權限
   （新增檔案需要）。
2. 三個 `TEMPLATE_FILE_ID_*` 指向的 Word 範本檔案——確認新擁有者
   帳戶至少有**檢視**權限（讀取範本只需要檢視）。
3. 如果範本檔案與輸出資料夾原本放在 Ivan 個人的「我的雲端硬碟」，
   考慮搬到教會共用的位置（見下一節），避免 Ivan 個人帳戶被停用時
   連帶檔案一起消失。

---

## 6. Shared Drive 成員

如果範本檔案、輸出資料夾放在教會的 Shared Drive（共用雲端硬碟）：

1. 確認幹事角色帳戶是那個 Shared Drive 的成員，權限至少是「內容
   管理員」（需要新增檔案）。
2. 確認試算表本身（如果也放在 Shared Drive）同樣有正確的成員與
   權限設定。
3. 如果目前還**沒有**用 Shared Drive（檔案放在個人雲端硬碟），強烈
   建議移交時一併搬過去——教會系統長期由一個人帳戶擁有全部檔案，
   是最常見的「人一走、系統跟著斷」的原因。

---

## 7. `Config` 內要換的 ID 與電郵

逐一檢查 `Config` 工作表內以下設定鍵，換成新的、教會長期擁有的資源：

| 設定鍵 | 內容 | 換的理由 |
|---|---|---|
| `ROSTER_SPREADSHEET_ID` | 職事表試算表 ID | 如果職事表本身也要換擁有者，記得同步更新 |
| `BULLETIN_OUTPUT_FOLDER_ID` | 週報輸出資料夾 | 如果搬到 Shared Drive，ID 會變 |
| `TEMPLATE_FILE_ID_NORMAL`／`TEMPLATE_FILE_ID_COMBINED_BAPTISM`／`TEMPLATE_FILE_ID_ANNIVERSARY` | 三個 Word 範本檔案 | 同上 |
| `WEBAPP_URL` | Web App 部署網址 | 重新部署後一定會變 |
| `PROTECTION_EDITOR_EMAILS` | 受保護工作表的例外編輯者電郵 | 確認名單是現任幹事，不是已離任的人 |

⚠️ 這些多數是 ID／電郵類欄位，本專案的硬規則是**一律 seed 成空字串，
不寫死在程式碼裡**（見 `tests/constants.test.js`），所以這些值只存在
`Config` 工作表本身，不會出現在 GitHub repo 的任何程式碼裡——移交時
不需要擔心 GitHub repo 洩漏這些資訊，但也代表**這些值只有這一份**，
換人之前務必先確認清單填齊，不要漏改。

---

## 8. GitHub repo 的處理

1. 本專案（`hwc-bulletin-automation`）是**公開** repo，不含任何真實
   ID、電郵、姓名（全部走 `Config`）——移交擁有權本身不需要對 repo
   做任何清理。
2. 如果新的維運者要接手改程式碼，把 GitHub repo 的**協作者權限**
   加給對方（Settings ▸ Collaborators），或者把 repo 轉移到教會的
   GitHub 組織帳戶下。
3. `.clasp.json`（本地開發環境用來指定要 push 到哪一個 Apps Script
   專案）**不在**版本控制內（已經被 `.gitignore` 排除），每個人的
   本機都要自己設定一次，指向正確的 Apps Script 專案 ID。
4. 交接時建議一併交出：這份 repo 的 clone 方式、`clasp login`／
   `clasp push` 的操作說明（見 repo 的 `README.md`，如果沒有請補上）。

---

## 9. `deploy.bat` 與 `deployment-id.txt`

repo 根目錄的 `deploy.bat` 是一鍵部署批次檔（Windows）：
`clasp push` → `git add` → `git commit` → `git push` → `clasp deploy`，
任何一步失敗就立即停止並講明原因。用法見
[幹事操作說明.md](幹事操作說明.md) 的「更新程式碼：`deploy.bat`」一節。

移交時要注意的兩點：

1. **`deployment-id.txt` 不在 repo 內**（已被 `.gitignore` 排除，
   因為它含真實的部署 ID）。新的維運者 clone 之後，`deploy.bat` 第一次
   跑會直接停下來，叫他自己建立這個檔案。
   - 內容：一行，只放 Web App 的部署 ID，不要加引號。
   - 那個 ID 在 **Apps Script ▸ 部署 ▸ 管理部署作業** 取得。
   - ⚠️ **移交後那個 ID 會不一樣**：新帳戶重新部署 Web App（見上面
     第 4 節）會產生新的部署，舊的 ID 不可以照抄過去。
2. **`deploy.bat` 本身沒有任何 ID**，可以放心公開，不需要在移交時
   清理任何內容。

跑完 `deploy.bat` 之後，畫面會提醒仍需人手做一件事：
**試算表 ▸ 週報系統 ▸ 初始化工作表**（新增了 Config 鍵或 `BulletinWeeks`
欄位時一定要撳；冪等，撳多幾次沒有副作用）。

---

## 移交完成後的驗收

先跑一次「檢查授權範圍」，確認新帳戶對全部 5 項服務都已經授權——這一步
沒過，後面的驗收多數會因為同一個原因（授權不足）失敗。

再跑一次「完成度自我檢測」，確認：

- 🔴 項目數為 0（尤其是職事表 ID、三個範本 ID、輸出資料夾）；
- 「觸發器」三項都顯示已安裝（用新帳戶重新裝過）；
- 「Web App 部署」顯示新的網址。

再用「全季流程演練」跑一次當季，確認整條流程用新的帳戶身分真的走得
通（尤其是 Word 產生與 Drive 寫入這兩步，最容易因為權限沒轉移乾淨而
失敗）。
