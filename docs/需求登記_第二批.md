## R-030　夏令時間家事報告自動加入　【已完成】（2026-08-26）

### 考證結果（由 88 期真實週報抽出）

只找到三則，格式穩定：

> **2025-03-30**（夏令時間完結前一週）
> 今年標準時間將於下主日(4月6日)正式開始。請各位嘉賓、朋友和弟兄姊妹於本週六晚將時間回撥一小時。

> **2026-03-29**（夏令時間完結前一週）
> 今年Daylight Saving於下主日(4月5日) 完結，請大家於本週六晚將時間回撥一小時。

> **2025-09-21**（夏令時間開始前一週）
> Daylight Saving將開始：今年Daylight Saving於下主日(28/9)開始，請於27/9星期六晚上將時鐘撥前一小時 (如圖)。

### 規則

紐西蘭夏令時間：**9 月最後一個主日開始，4 月第一個主日完結**。
提示一律登在**改動當日的前一個主日**那一期。一年兩次。

### 設計

Config 兩條範本，可改：

| 鍵 | 預設值 |
|---|---|
| `DST_START_ANNOUNCEMENT` | `Daylight Saving將開始：今年Daylight Saving於下主日({{CHANGE_DATE}})開始，請於{{SATURDAY}}星期六晚上將時鐘撥前一小時。` |
| `DST_END_ANNOUNCEMENT` | `今年Daylight Saving於下主日({{CHANGE_DATE}}) 完結，請大家於本週六晚將時間回撥一小時。` |
| `DST_ANNOUNCEMENT_SEQ` | `5`（排在家事報告的次序，數字細者在前） |
| `DST_AUTO_INSERT` | `TRUE` |

- 建立該季週報時，**由日期計算**出該季有沒有夏令時間轉換的前一個主日，
  有就自動寫入內容表的 `家事報告`，`SEQ_NO` 用 `DST_ANNOUNCEMENT_SEQ`
- **不要硬寫日期表**。用「9 月最後一個主日」「4 月第一個主日」計出來，
  這樣 2030 年都仍然啱
- 寫入之後由使用者自行修改或把「有效」改 `FALSE`，系統不再覆寫
  （加一欄 `SOURCE=SYSTEM_DST` 標明來源，重建季度時只覆寫未被人手改過的）
- `{{CHANGE_DATE}}`、`{{SATURDAY}}` 的格式跟隨現有日期格式設定

⚠️ 2025-09-21 那則原文有「(如圖)」，指週報有一張時鐘圖。範本預設**不含**這句，
需要圖就由幹事自己在內容表加，因為系統不處理圖片。

## R-031　誦讀按四個月輪替　【已完成，已考證】

## R-032　內容過多時的分頁規則　【未開始，欠資料】

### 現時知道的

由 88 期的內容量分析：

- 中位數約 4,500 位元組，最長的幾期約 6,400，多出約四成
- 最長那幾期：`2026-02-22`、`2025-08-10`、`2026-07-19`、`2025-11-02`、`2025-12-14`
- 撐大的主因有三個：
  1. 家事報告條數多，而且每條有自己的小標題
     （`2025-11-02` 有 10 條：年標、NCD 報告、堂委主席安排、培訓報告、換屋頂、
     財務部消息、報佳音、短宣報名、社區講座、肢體消息）
  2. 代禱事項每條有小標題（同期 5 條）
  3. 兩張財政表同期出現（綜合收支 ＋ 特殊海外奉獻及慈惠）

### 做不到的

Project files 是純文字擷取，**抽不到頁數**，所以我無法確認哪幾期真的是 5 頁，
更無法看出第 5 頁放了什麼。

### 需要的

在 Drive 找出真正 5 頁或以上的那幾期，上載**真的 .docx 或 PDF**（三份就夠）。
有了真檔案我可以看出：

- 第 5 頁承接的是哪一段（家事報告下半、代禱、團契、還是財政）
- 原本 4 頁保留了什麼
- 分頁是硬分頁符還是自然流動

之後才可以定規則，例如「家事報告超過 N 條就整段移到第 5 頁」，
或者「財政表兩張同期出現時，第二張移到第 5 頁」。

**在有真檔案之前，不要寫任何溢出邏輯。**

## R-033　預覽連結 ＋ 每星期一寄給 CC、DB、幹事　【未開始】

### 需求

- UI 加一條「預覽」連結，CC、DB 可以看**下一個主日**的最新版本
- 每星期一自動把這條連結寄給 CC、DB、幹事
- 內容是「目前為止的狀態」：職事表抓到的、表單填了的、任何人改過的，
  幹事未必動過手
- **與 master 連結不同**：master 是幹事正式發佈的定稿；預覽是每週都會變的草稿

### 設計

- 另建一個**固定的預覽 PDF 檔案**（與 master 同樣做法，ID 永不變），
  Config `PREVIEW_PDF_FILE_ID`
- 但預覽不能靠幹事用 Word 另存——那正是要避免的。所以預覽用
  **Google Docs 轉換的 PDF**，版面會走樣，接受
- 預覽信與預覽頁面**必須明確標示**：
  `這是草稿預覽，版面與正式印刷版不同，只供核對內容用`
- 星期一觸發器同一支，順手多做一件事：產生預覽、覆寫預覽檔案、寄連結
- Config `PREVIEW_SEND_GROUPS`（預設 `CC,DB,ADMIN`）、`PREVIEW_ENABLED`

⚠️ 決策點：預覽用 Google Docs 轉換是**刻意接受版面走樣**，
因為預覽的用途是核對「講員是誰、家事報告寫了什麼」，不是核對版面。
如果你認為走樣的版面會令堂委誤會，另一個做法是預覽直接給 **.docx 下載連結**，
不做 PDF。兩者揀一個，我建議前者（手機開得到）。

## R-034　主日選單改為兩層　【已完成】（2026-08-26）

現時是一條完整日期清單，季度一多就長到不能用。

### 建議

```
季度：[2027T4 ▼]        主日：[2027-11-07 ▼]   [← 上一個] [下一個 →]
```

1. **季度下拉**：只列有資料的季度，預設選中「下一個要寄的主日」所屬的季度
2. **主日下拉**：只列該季的主日，每項後面加狀態標記，例如
   `2027-11-07　已發佈 第 2 版`／`2027-11-14　待填 12 項`
3. **上一個／下一個箭嘴**：跨季度時自動切換季度下拉
4. 開啟 UI 時**預設落在「下一個未發佈的主日」**，不是清單第一項——
   九成情況這就是要做的那一期

狀態標記是重點：幹事最常問的是「邊幾期未搞掂」，把答案放進下拉就不用另外找。

## R-035　只保留本季與前一季可見，更早自動封存　【未開始】

### 設計

Config `RETENTION_QUARTERS_VISIBLE`（預設 `2`，即本季 ＋ 前一季）。

- **不刪任何資料。** `BulletinWeeks` 加一欄 `ARCHIVED`，
  超出保留範圍的季度設 `TRUE`
- UI 的季度下拉預設不顯示已封存的，加一個「顯示已封存」勾選格
- 季度填寫表（`Fill_*`）：超出範圍的隱藏工作表（`hideSheet()`），不刪
- 內容表本身一季一個檔案，天然封存：把 `ContentSheets` 該行 `ACTIVE=FALSE`，
  並把檔案移入 `週報內容表/封存` 子資料夾
- **自動執行時機**：每次「建立本季週報」與每季提示觸發器順手跑一次封存檢查
- 封存動作一律寫 `AuditLog`，並在對話框回報封存了哪幾季

⚠️ 封存不可以令舊資料無法查閱。「顯示已封存」一勾就要看得回，
`Diagnostics` 與 `PublishLog` 完全不受影響。

## R-036　職事表沒有該季資料時仍可建立週報　【已完成】（2026-08-26）

### 需求

例如目前是 2029T1 而職事表未有該季，使用者仍然可以建立該季週報，
事奉格留空，之後職事表有資料時再補抓。

### 設計

1. 「建立本季週報」不再因為職事表找不到而中止。改為建立成功，
   事奉相關欄位留空
2. `BulletinWeeks` 加一欄 `ROSTER_STATUS`：`OK` / `NOT_FOUND` / `PARTIAL`
3. UI 頂部黃色橫幅：
   `本季職事表未有資料，事奉欄位全部留空。職事表建立好之後，撳「從職事表補抓」。`
4. 新增按鈕「**從職事表補抓**」：
   - 隨時可以重試
   - **只填空白格**，不覆寫人手已填的值（沿用現有三向比對）
   - 完成後顯示補了多少格、仍有多少格空白
5. 完成度自我檢測加一項：列出仍是 `NOT_FOUND` 或 `PARTIAL` 的季度
6. 星期一自動寄出：職事表找不到時**不要當成錯誤**，
   改為寄出但在信中註明「本期事奉資料尚未確定」
   （現時會拋 `ROSTER_NOT_FOUND` 並中止，`ErrorLog` 已有一筆 2026-08-24 的紀錄）

## R-037　示範與正式上線前的環境整理　【未開始】

### 要處理的

| 項目 | 處理方式 |
|---|---|
| 測試季度 `2027T4` 的資料 | 不刪，設 `ARCHIVED=TRUE`（見 R-035） |
| 沙盒季度 `2028T4` | 保留，自測機要用；確認永遠不會出現在使用者的季度下拉 |
| `PublishLog` 內 `IS_SELFTEST=TRUE` 的行 | 頂部狀態列與正式報表要排除，只計正式發佈 |
| 沙盒 master 檔案 | 保留，但確認 `SELFTEST_MASTER_PDF_FILE_ID ≠ PUBLISHED_PDF_FILE_ID` 的斷言仍在 |
| `Recipients` | 補齊 CC、DB、IT（R-029） |
| `DRY_RUN` | 示範時 `TRUE`；正式上線當日才改 `FALSE` |
| 觸發器 | 確認只安裝一個星期一觸發器，沒有重複 |
| `ErrorLog` | 示範前清一次，或至少確認最近 7 日沒有舊錯誤殘留 |
| 內容表樣本資料 | 示範用的內容表要另建一個，不要用 `2027T4` 那個 |

### 最重要的一次示範：由新季度從零開始

要寫一份 `docs/示範腳本.md`，逐步列明：

```
1. 建立本季週報（由職事表抓事奉資料）
2. 建立本季內容表
3. 寄內容表連結給 CC、DB
4. （堂委填內容表）
5. 從內容表匯入
6. 在 UI 補填講員、講題、讀經
7. 產生 Word → 用 Word 核對 → 另存 PDF
8. 發佈到 master 連結
9. 寄出通知
10. 下一個星期一，觸發器自動寄預覽給 CC、DB
```

每一步寫明：去邊度、撳咩、預期見到咩、失敗時點算。
這份腳本同時是你向堂委會、執事會簡報時的流程。
