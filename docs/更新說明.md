# 更新說明（CHANGELOG）

版本號＝部署日期 `yyyy.MM.dd`（同一日第二次部署加 `-2`）。程式內的版本在 `src/Constants.gs` 的 `APP_VERSION`，
試算表選單「關於本系統」、填寫介面頁底、「設定差異檢查」報告都會顯示。**每次改版，最上面加一段同一個版本號**
（`tests/version.test.js` 核對兩邊一致）。每段寫：改了甚麼、部署之後要做甚麼（例如「初始化工作表」）、有沒有新 Config 鍵。

給其他堂會或其他教會的維護者：先看自己的版本號（「關於本系統」），再由那一個版本之後的各段逐段看。

## 2026.11.17-2

效能（需求 R-060、R-061；2026-11-17 全系統檢查之後）：

- **從內容表匯入改為批次寫入，並加時間預算**（R-060）：整季匯入 13 週以前約 6 分鐘（貼近 Apps Script 的上限），原因是每一格改動都重新讀整張
  `BulletinWeeks` 找那一行、寫一格，再逐筆寫 `AuditLog`。現在同一個主日的改動欄位一次寫入（純文字欄仍然先設純文字格式再寫，數字不會被轉型），
  `AuditLog` 整份匯入一次寫入；寫入之後工作表的內容、`AuditLog` 每一行的內容與先後次序與以前完全相同。13 週、每週 15 格改動的測試：
  `BulletinWeeks` 寫入 195 次 → 13 次，`AuditLog` 寫入 234 次 → 1 次。
- **匯入有時間預算**（新 Config `IMPORT_TIME_BUDGET_SEC`，預設 240 秒）：以主日為單位寫入，用完預算就在寫好一個完整主日之後停下，
  畫面與選單都會講「已匯入 N／M 個主日，請再按一次繼續」（不會留下寫到一半的主日）。內容表自動同步停下時不記修改時間，下一次觸發繼續，
  AuditLog 摘要行講明做了幾個主日。每個主日的版本改為在該主日寫入之前才存（內容與數目不變）。
- **儲存加分段計時，並且減少讀寫**（R-061）：儲存之後，頂部「伺服器用時」顯示儲存各段（檢查、拿鎖、讀現況與比對、存版本、寫入、AuditLog……）用了多少秒，
  按一下看分段，隨後重新載入的用時併進來一起顯示。同一次儲存之內同一張工作表只讀一次（鎖之內讀的記憶在任何寫入之後即時清走，鎖外讀的在拿到鎖時作廢），
  同一行的欄位合併寫入、整次儲存的 `AuditLog` 一次寫入。樂觀鎖、三方比對、版本快照、`LAST_SAVED_AT`、`AuditLog` 的內容與次序都沒有改。
  典型的一次儲存：`BulletinWeeks` 讀 10 → 7、寫 5 → 4，`AuditLog` 寫 5 → 2。
- 部署之後：**要按「初始化工作表」**（新 Config 鍵 `IMPORT_TIME_BUDGET_SEC`；不按的話儲存會被「工作表結構落後」擋住）。不用重新安裝觸發器。
  部署後儲存一週，按頂部「伺服器用時」看分段，再決定下一步（詳見 docs/待確認事項.md「KK（續）效能」）。

## 2026.11.17

上線前安全修正（2026-11-17 全系統檢查之後；需求 R-035 修正、R-055 至 R-059）：

- **舊季度封存改按「今日所在季度」計算**（R-035 修正）：以前把季度編號由新到舊排，只留最新 N 季；週報內有未來的測試季度
  （2028T2 等）時，今季與上線季被排到「要封存」，只是靠「未發佈而且有內容」那一道檢查擋住——空白的新季度（上線時的 2027T1）
  沒有這一道保護，會在星期一被封存。現在：保留今日所在季度連之前共 `RETENTION_QUARTERS_VISIBLE` 季，比它更舊的才封存；
  今日所在季度與之後的季度永遠不會被自動封存。今日用真正的今日（Config `SYS_TIMEZONE`，不看模擬今日）。
  算不出今日所在季度時一季都不封存，並寫 ErrorLog（`RETENTION_NO_CURRENT_QUARTER`）。
- **選單「封存指定季度…」**（R-055）：清理測試季度用。輸入季度 ID，對話框列出主日數、未發佈而且有內容的主日、內容表會怎樣，
  按確定才封存；沙盒季度拒絕；今日所在季度要再確認一次。一格資料都不刪，隨時可以用「取消封存季度」還原。
  同時修好一個舊問題：「取消封存季度」以前找不到已經封存（有效＝FALSE）的內容表登記行，內容表登記行不會還原。
- **內容表自動同步：暫時性失敗要再試**（R-056）：Google 暫時出錯（「Service Spreadsheets timed out」等）以前一失敗就當作
  已處理，要等內容表再有改動才再試。現在同一個修改時間連續失敗未滿 3 次會再試，ErrorLog 只記第 1 次與第 3 次，第 3 次起
  內容表有改動才再試。沒有今日及之後主日的季度不再呼叫 Drive。結構性失敗（例如版面過舊）的「不再試」記錄由七日改為 30 日。
- **每日管理員摘要電郵**（R-057）：每日觸發器最後一段。上一次摘要之後有觸發器錯誤，或者星期一自動流程本週未見執行，才寄給
  管理員（沒有就不寄）。新 Config：`ADMIN_DIGEST_ENABLED`（預設 TRUE）、`ADMIN_DIGEST_EMAILS`（預設空白＝Recipients 內 ADMIN 與
  IT 組）。新電郵範本 `ADMIN_DIGEST`。受 `EMAIL_ALLOWLIST` 與 `DRY_RUN` 限制（試行時只寫 SendLog 一行）。
- **「上線前檢查」加四項**（R-058）：寄送名單、收件人是否仍是測試名單、測試季度、時區一致；時區一致亦加入「完成度自我檢測」。
- **自動觸發器加 `nearMinute()`**（R-059）：星期一寄送與每日建立季度兩個觸發器按 Config `SEND_MINUTE` 指定大約的分鐘
  （Apps Script 的誤差是前後 15 分鐘）。以前只有小時，實際執行時間在該小時內任何時候。
- 部署之後：
  1. **要重新按一次「安裝自動寄送觸發器」**（`nearMinute` 要重新安裝才生效）。
  2. **要按「初始化工作表」**（兩個新 Config 鍵；EmailTemplates 加 `ADMIN_DIGEST` 一行）。
  3. 用「上線前檢查」看新增的四項；不再用的測試季度用「封存指定季度…」收起。
