### F5【中】改回與內容表相同的值，覆寫不會解除

成因：`computeFieldOverridePlan_()` 判斷「改回同內容表一樣」比的是 `SOURCE_VALUE_AT_OVERRIDE`（覆寫當時的來源值），不是內容表**現在**的值；匯入遇到「週報現值＝內容表值」就直接 return，不碰覆寫行。於是內容表建立前就在介面填過的欄位、以及內容表改值之後才改回的欄位，都永遠解除不了，之後內容表再改，匯入一律報「你自己改過」。

修法：匯入時（預覽與套用走同一組計算），對這次匯入範圍內每一個啟用中的第三種欄位覆寫，若內容表現值＝覆寫值，把該覆寫設為 `ACTIVE=FALSE`（不刪行），記 `AuditLog` 的 `FIELD_OVERRIDE_RELEASE`；對話框在 ✋ 那一段之後加一句：

- 預覽：`ℹ️ 有 N 格你之前改過的值，現在已經與內容表一致，將會從此改回跟隨內容表。`
- 套用後：`ℹ️ 有 N 格你之前改過的值，現在已經與內容表一致，已從此改回跟隨內容表。`

- 程式：`src/ContentImport.gs`（`computeContentImportPlan_()` 的 `plan.releases`、`releaseFieldOverrides_()`、`buildContentImportDialogLines_()`）
- 測試：`tests/fieldoverride.test.js` 第 8 組（經 `applyContentImport_()`／`previewContentImport_()`）

## 二、這一輪順帶發現的問題（已修）

### 單一主日匯入會改到其他主日的「週欄位」

重現：內容表「崇拜程序」有兩個主日，週報兩個主日的講題都是舊值；只匯入第一個主日
（`applyContentImport_(quarterId, { isoDate })`）之後，**第二個主日的講題也被改成內容表的新值**。

成因：`computeContentImportPlan_()` 處理 `WEEK`／`WEEK_ATTENDANCE` 兩種分頁（宣召、
崇拜人數、崇拜程序、浸禮合堂）時，迴圈走的是 `Object.keys(byDate)`（整季），沒有按
`input.serviceDates` 篩選；只有清單類的分頁才按 `serviceDates` 篩。對話框卻說
「只匯入選定的一個主日」。有覆寫的欄位不受影響（走 `CONFLICT`）。

修法：週欄位類的迴圈開頭加主日篩選，範圍外的主日整個略過；篩選排在「BulletinWeeks 沒有
這一行」的警告之前，範圍外的主日不再出警告。F5 解除覆寫原本自己另有一份範圍判斷，
併入同一個篩選，不留兩份。

- 程式：`src/ContentImport.gs` `computeContentImportPlan_()`
- 測試：`tests/contentimport.test.js` 的「範圍 1 至 4」（宣召、崇拜人數、警告範圍、預覽與套用數字一致）、`tests/fieldoverride.test.js` 的「範圍：崇拜程序」；已驗證把篩選拿掉測試會紅
