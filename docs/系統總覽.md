# 系統總覽

一頁講清楚「週報自動生成系統」是什麼、資料由邊度嚟、每星期會自動發生
什麼、每張工作表的角色，以及與職事表的關係。詳細操作請見
[幹事操作說明.md](幹事操作說明.md)；技術細節請見
[工作表結構.md](工作表結構.md)。

---

## 一句話講清楚系統做什麼

這個系統負責**基督教中國佈道會奧克蘭聖道堂粵語堂**每星期週報的資料
管理、Word 檔產生，以及自動寄送——幹事與領詩只需要在網頁填寫介面或
「季度填寫表」打好內容，系統會自動：

1. 由**職事表**（另一個獨立試算表，唯讀）取得當週的事奉安排；
2. 組出完整的週報資料模型（程序表、事奉框、人數表、家事報告……）；
3. 按範本產生一份 `.docx` 週報；
4. 星期一自動寄一封含週報全文（連 `.docx` 附件）的電郵給堂委、執事。

**版面 100% 由 Word 範本決定**——系統從來不重新排版，只把範本上的
佔位符換成當週的真實內容。

---

## 資料由邊度嚟

系統橫跨**兩個試算表**：

| 試算表 | 角色 | 本系統對它的權限 |
|---|---|---|
| **粵語堂職事表**（獨立試算表） | 事奉排班的**唯一真相**——邊個崗位邊個人 | **唯讀**，一個位元都不會寫入 |
| **本系統的試算表**（週報系統） | 週報內容、設定、記錄，全部由本系統管理 | 讀寫 |

⚠️ **這條唯讀邊界是本系統最重要的設計原則**，有兩層防線鎖住：
`src/RosterRead.gs` 是唯一准許呼叫 `SpreadsheetApp.openById()` 開啟
職事表的檔案，而且那個檔案裡沒有任何寫入方法；`tools/lint-readonly-roster.js`
每次都會靜態掃描整個原始碼確認這一點沒有被破壞。

事奉安排（邊個崗位邊個人）永遠以職事表為準；週報自己的內容（程序表、
人數、家事報告、代禱、財政、團契……）由幹事、領詩透過填寫介面或季度
填寫表輸入，存在本系統的試算表內。

## 每星期會自動發生什麼

系統安裝好「自動寄送觸發器」之後，每個星期一（可在 `Config` 調整星期
與時辰）會自動：

1. 依 `Config` 的 `SEND_TARGET_OFFSET_DAYS` 算出「下一個主日」；
2. 檢查職事表跟週報有沒有分歧（例如幹事覆寫過的事奉，職事表那邊又
   改了），有的話寄一封提醒信給幹事；
3. 檢查有沒有新一季職事表已經生成、但季度填寫表還沒建立——有的話
   自動建立並寄出填寫邀請；
4. 組裝週報內容、產生 Word 附件、寄給堂委與執事（`Config` 的
   `DRY_RUN=TRUE` 時只記錄不會真的寄出——這是系統預設，也是唯一
   安全的「先試後寄」機制）。

⚠️ Apps Script 的時間觸發器**不保證準時**（只能指定小時，不能指定
分鐘），詳見 [幹事操作說明.md](幹事操作說明.md)。

## 工作表角色一覽

試算表目前定義了 **23 張固定工作表**，另外每一季會動態產生一張
`Fill_<季度>`（例如 `Fill_2027T4`）季度集中填寫表。

| 工作表 | 角色 | 誰填寫 |
|---|---|---|
| `_README` | 說明每張表的用途（本文件的精簡版，寫在試算表內） | 系統預先填入 |
| `Config` | 全系統參數設定（時區、範本 ID、寄送規則……） | 人手 |
| `BulletinWeeks` | 一個主日一行，週報全部內容欄位 | 人手為主，狀態欄系統寫 |
| `Announcements` | 家事報告內容 | 人手 |
| `Prayers` | 代禱事項／宣教消息 | 人手 |
| `Fellowships` | 本週團契聚會資訊 | 人手（可由常設時間表自動產生） |
| `Finance` | 月度財政報告 | 人手 |
| `PersonDisplay` | 姓名的尊稱與顯示覆寫規則 | 可自動建骨架，人手調整 |
| `HonorificLookup` | 「姓名 → 尊稱」對照表（貼上用） | 人手 |
| `PostDisplay` | 崗位顯示名稱、次序、合併規則 | 系統預填，人手可調 |
| `MergeGroups` | `PostDisplay` 用的合併組定義 | 系統預填，人手可調 |
| `ProgramTemplates` | 崇拜程序範本（平常／浸禮／堂慶） | 系統預填，人手可增補 |
| `Recipients` | 週報收件人名單 | 人手 |
| `EmailTemplates` | 寄送用的電郵範本文字 | 系統預填，人手可改 |
| `Diagnostics` | 唯讀診斷報告存放處（每次執行覆蓋重寫） | 系統寫 |
| `AuditLog` | 系統對試算表所做的每一次異動記錄 | 系統寫，只增不改 |
| `SendLog` | 每一次寄送嘗試的記錄 | 系統寫，只增不改 |
| `ErrorLog` | 系統偵測到的例外狀況 | 系統寫，只增不改 |
| `DutyOverride` | 幹事在週報直接覆寫事奉名單的記錄 | 系統寫 |
| `ConflictNoticeLog` | 各種「已經提醒過」指紋，避免重複轟炸收件人 | 系統寫 |
| `FellowshipDefaults` | 團契聚會的常設時間表 | 系統預填 3 行，人手調整 |
| `FillSnapshot` | 季度填寫表與 `BulletinWeeks` 三方比對用的快照 | 系統寫，人手唯讀 |
| `FillBackup` | 季度資料的版本備份 | 系統寫 |
| `Fill_<季度>`（動態） | 季度集中填寫表，一季一張，一行一個主日 | 人手（前三欄唯讀，來自職事表） |

## 與職事表的關係與唯讀規則

- 職事表決定「邊個崗位邊個人」，週報系統只**讀取**這個結果。
- 幹事可以在填寫介面或季度填寫表**直接覆寫**某個崗位的姓名（例如
  臨時換人）——這個覆寫**只存在週報**，永遠不會寫回職事表；職事表
  之後再改，系統只會標成「衝突」，讓幹事自己決定要不要跟。
- 職事表的季度、主日日期、特別主日安排，週報系統**照單全收**，不會
  自作主張調整。
- 職事表試算表的**版本記錄**（Google Sheets 的修訂記錄）不應該因為
  本系統的任何操作而新增——每一次改動（不論是 Ivan 手動操作，還是
  用 Claude Code 開發新功能）都應該用「檢查職事表分歧」「全季流程
  演練」這類**唯讀**工具先驗證，確認系統真的沒有寫入職事表。
