# 幹事操作說明

本文件寫給每星期實際操作「週報系統」的幹事看，**按實際的一星期工作
次序編寫**，不是按功能列表——照著標題順序看下去，就是幹事一星期會
遇到的事情次序。技術細節（工作表結構、程式架構）請見
[工作表結構.md](工作表結構.md)；系統整體介紹見
[系統總覽.md](系統總覽.md)。

## R-038：日常操作以填寫介面為主，選單降級為維護用途

⚠️ **這一節先讀。** 由 R-038 起，幹事整條例行流程都可以在**填寫介面**
（網頁版）完成，**不需要轉去試算表選單**。

試算表選單**全部保留**，但它的角色改變了：

| | 用來做什麼 | 誰用 |
|---|---|---|
| **填寫介面（網頁）** | **日常全部操作**——每週填寫、每季作業、檢查、發佈 | 幹事 |
| 試算表選單 | 維護、診斷、災難復原（例如填寫介面開不到、要看 `Diagnostics` 的完整報告） | IT／管理者 |

兩邊**用同一份底層邏輯**，所以不會出現「介面做了一次、選單再做一次」
這種情況；同一件事在兩邊做，結果一樣。

### 「季度作業」區塊在哪裏

開填寫介面，捲到最底「發佈及匯出」**上面**，有一個摺疊住的
**「季度作業（<季度>）」**。撳標題展開。

⚠️ 預設摺疊是刻意的：這一組是**一季做一次**的事，攤開在眼前會把每星期
真正要做的事推落下面。

括號內那一季，是系統自己算出來的「目前應該處理哪一季」，**不一定等於
頁頂主日下拉那一季**——頁頂選的是一個主日，這裏做的是整季的事。
撳之前看清楚括號內那個季度。

### 八粒按鈕

**第一組　建立與收集**（會改資料，每粒都先預覽後確認）

| 按鈕 | 做什麼 | 會不會覆寫 |
|---|---|---|
| 建立本季週報 | 為本季每一個主日建立一行空白週報 | **不會**——已經存在的日期一格都不改 |
| 建立／刷新本季內容表 | 未有就建立一個；已經有就只刷新版面與下拉 | **不會**——同工填落去的資料一格都不改 |
| 寄出內容表連結 | 把內容表連結寄給堂委、執事、幹事 | 不適用（只寄信） |
| 從內容表匯入（整季） | 把整季的家事報告、代禱、團契、財政匯入週報 | 會（所以先看預覽那四個數字） |

**第二組　檢查**（全部唯讀，一格都不會寫）

| 按鈕 | 做什麼 |
|---|---|
| 本季待填清單 | 整季還有哪些欄位未填 |
| 檢查職事表分歧 | 週報與職事表哪幾格對不上（本系統不會改職事表） |
| 上線前檢查 | 八項系統狀態，🟢／🟡／🔴 |
| 發佈版本記錄 | master 那個 PDF 檔案的歷史版本 |

四個報告都在區塊下方展開一個**可捲動**的面板，右上角有「收起」。

### 三件要留意的事

1. **每一粒都會先講明將會發生什麼，你確認之後才會真的執行。**
   看到預覽之後想收手，撳「取消」——系統會回一句「已取消，一格都沒有寫」。
2. **「寄出內容表連結」旁邊會顯示 `DRY_RUN` 的現值。**
   `DRY_RUN=TRUE` 的意思是**不會真的寄出任何郵件**，只會在 `SendLog`
   記一筆。確認視窗第一句會再講一次。這是唯一一粒會真的寄信出街的按鈕。
3. **「重新匯入（只限這一個主日）」跟「從內容表匯入（整季）」是兩件事。**
   前者在唯讀區塊上方，只匯入你目前選住那一個主日；後者在「季度作業」
   區塊，整季一次過。兩者範圍不同是刻意的，不是重複。

### 唯讀報告不會清走 `Diagnostics`

⚠️ 這一點值得知道：`Diagnostics` 工作表**每次執行清空重寫，只保留最新
一份報告**。所以填寫介面那四個唯讀報告**一律只在畫面顯示，不寫
`Diagnostics`**——否則你在介面撳一下，就會把 IT 剛跑完的診斷報告清走。

要一份寫得入 `Diagnostics`、可以慢慢核對的完整報告，用**選單**那一邊。

## 星期一：系統自動寄出下主日週報

如果已經撳過選單「安裝自動寄送觸發器」，星期一（或 `Config` 設定的
其他日子）系統會**自動**：

1. 算出下一個主日，檢查職事表跟週報有沒有分歧，有的話寄一封提醒信
   給幹事（`Recipients` 的 `ADMIN` 組）；
2. 新一季進入提前通知期而未寄過邀請的，自動建立內容表並寄出邀請（內容表 v2 起不再建立
   季度填寫表；舊版內容表要人手按「建立／刷新本季內容表」移轉，自動流程只會略過）；
3. 組裝週報內容、產生 Word 附件、寄給堂委與執事——**除非
   `Config` 的 `DRY_RUN` 是 `TRUE`（系統預設），這一步只會在
   `SendLog` 留一筆記錄，不會真的寄出任何郵件**。

⚠️ **`DRY_RUN` 是全系統共用的一個開關**，不是「這一次操作要不要試行」
的選項。如果為了手動測試把它改成 `FALSE`，忘記改回 `TRUE`，下一次
自動觸發也會是真的寄送。建議養成習慣：測試完立刻改回 `TRUE`。

⚠️ Apps Script 的時間觸發器**只能指定「小時」，不能指定「分鐘」**，
而且**不保證準確在該小時執行**——實際觸發時間可能比預定時間晚數十
分鐘，甚至更久。這是 Google Apps Script 平台本身的限制，不是本系統
的 bug。

**幹事這一天要做的事**：如果收到「職事表分歧」提醒信，撳選單
「檢查職事表分歧」逐項確認要跟職事表還是保留週報自己的版本。如果
收到「內容表連結」的邀請信，代表新一季已經開始，見下面「每季一次」那一節。

## 平日：填寫本星期的內容

撳試算表選單「週報系統 ▸ 開啟填寫介面」，網頁介面填好本星期的崇拜
程序、人數、家事報告、代禱事項、團契、財政資料。每一格填完撳
「儲存」即可。事奉名單如果要臨時改動，同樣可以在這個介面直接
改——見下面「直接修改事奉名單」一節。

儲存之後的訊息（G16）：「已儲存，更新了 N 個欄位。」的 N 是你改了幾個欄位（週報欄位、
本週事奉與下週事奉的每一格各算一個）。改講題、讀經經文、回應詩歌這類內容表欄位時，系統
另外記一筆「覆寫記錄」，那一筆不計入 N。如果見到「已儲存。欄位內容沒有改變，只更新了 N 筆
覆寫記錄（……）」，即是畫面上的欄位一格都沒有變，系統只是整理覆寫記錄（例如取消一個已經
與內容表或職事表相同的覆寫），最後儲存時間會更新，這是正常的。

如果想一次過填完**整季**（例如領詩想一口氣填完一季的詩歌），在本季內容表的「崇拜程序」
分頁填，一個主日一行，再在填寫介面匯入。（以前的「季度填寫表」內容表 v2 起已停用。）

核對內容：撳選單「預覽週報郵件內容」，看看這一週的郵件會長什麼
樣——事奉框、程序表、人數表等有沒有明顯錯漏。這個動作**不會寄出任何
郵件**，可以隨時撳、撳幾次都沒關係。

### 浸禮三堂聯合崇拜那一週

浸禮合堂那一週，填寫介面會**多出一段「丙之二、浸禮合堂（副框）」**
（其餘主日這一段會自動隱藏，不用理會）。六格分兩類：

- **三個「主禮」**——每格**一位**，填姓名即可，系統會自動加尊稱
  （規則與事奉框完全一樣）。
- **三個名單欄**（受浸肢體／入會肢體／奉獻孩童）——可以填**多位**，
  用**空格分隔**。系統會**原樣印出**，不會自動加尊稱、不會重新排序，
  所以你怎樣排就怎樣印。

沒有的那一項**直接留空**就可以：

- 某一行兩格都留空 → 週報上**整行不會出現**（例如那期沒有孩童奉獻禮）。
- 六格全部留空 → 整個副框都不會出現。

⚠️ 隱藏了不等於清空——如果某一週本來是浸禮、後來改回平常主日，已經
填好的名單仍然保留在系統內，改返浸禮就會再看到。

## 產生週報 Word 檔、檢查、交付印刷

### 產生單一主日

選單「產生本週週報（Word）」，輸入主日日期，系統會產生一份 `.docx`
存到 `Config` 的 `BULLETIN_OUTPUT_FOLDER_ID` 指定的資料夾。用 Word
開啟檢查版面、內容都對，就可以直接交付印刷——**系統交付的是
`.docx`，不是 PDF**，理由與版面保留有關，見
[Word範本製作指引.md](Word範本製作指引.md) 檔頭的說明。

每個主日只保留一份最新的檔案。 檔案放在輸出資料夾之下以季度 ID
命名的子資料夾內，例如 `2027T4/2027-11-07_粵語堂週報.docx`（子資料夾
不存在時系統會自動建立；想改為全部放在輸出資料夾本身，把 `Config`
的 `OUTPUT_GROUP_BY_QUARTER` 改為 `FALSE`）。同一個主日再產生一次，
系統會直接更新同一個檔案，不會多出 `(2)`、`(3)`，檔案連結也不變；
上一次的內容可在雲端硬碟用右鍵 ▸「管理版本」找回。

填寫介面「發佈及匯出」的「下載 Word」按鈕下面有兩條連結：「開啟最新
Word 檔（檔名，最後產生：時間）」與「開啟本季 Word 資料夾」；這個主日
還沒有產生過，就會顯示「這一週還未產生過 Word 檔」。

以下四個動作走同一個存檔流程，每次都是更新同一個最新版，並把檔案
記進 `BulletinWeeks` 的 `DOC_ID`：

1. 選單「產生本週週報（Word）」；
2. 選單「產生本季全部週報（Word）」；
3. 填寫介面的「下載 Word」（除了下載到本機，也同時更新雲端硬碟上的
   最新版；雲端存檔失敗時，下載照樣成功，並附一則警告）；
4. 星期一自動寄出的郵件附件（只在真的寄出時；`DRY_RUN` 為 `TRUE` 時
   只寫 `SendLog`，不碰雲端硬碟）。

因此星期一郵件附的 Word，與雲端硬碟上的最新版是同一份內容。

⚠️ 如果有人手動在同一個資料夾內放了另一份同名檔案，系統只更新其中最舊
的一份，並在對話框提醒；系統不會自動刪除任何檔案，請人手整理。

### 一次過產生整季

選單「產生本季全部週報（Word）」，輸入季度 ID（例如 `2027T4`），
系統會逐個主日產生 Word 檔，單一主日產生失敗不會中斷其餘的，最後
回報成功／失敗的數目，完整結果寫在 `Diagnostics` 工作表。

⚠️ 如果季度主日很多、執行時間接近 Apps Script 的 6 分鐘上限，系統
會**安全中止**並提示「已完成 N／M，請再按一次『產生本季全部週報』繼續」——已經產生過的
主日不會重新做一次（用 `BulletinWeeks` 的 `LAST_GENERATED_AT` 判斷），
再撳一次選單就會接著做剩下的。

### 檢查

撳「檢查範本佔位符」，看看範本用到的佔位符系統有沒有全部提供、有
沒有疑似被 Word 拼寫檢查切斷的佔位符——**這一步應該在每次改動範本
之後都做一次**，不要等印出來才發現漏字。

## 每季一次：新一季開始的時候

⚠️ **由 R-038 起，下面這幾步全部可以在填寫介面的「季度作業」區塊做完**
（見本文件最前面那一節）。以下寫的是**選單**那一條路，保留作維護用途——
兩邊做的是同一件事，做過一邊就不用再做另一邊。

正常的一季次序是：

```
建立本季週報 → 建立／刷新本季內容表 → 寄出內容表連結
   → （堂委執事填內容表）→ 從內容表匯入（整季）→ 本季待填清單
```

（內容表 v2 起「建立季度填寫表」「寄出填寫邀請」兩步已停用；內容表連結由「寄出內容表連結」寄給
`Config` 的 `CONTENT_SHEET_INVITE_GROUPS`，「停用舊功能」已把領詩 `WORSHIP` 加入。）

3. **產生本季團契**：按「季度工具 ▸ 由常設時間表產生本季團契」，
   系統會依 `FellowshipDefaults` 的常設時間表自動補齊整季的團契聚會
   資料（已經存在的不會重複、也不會被覆蓋）。

💡 這三步都是**冪等**的——重複執行不會產生重複資料，也不會覆蓋人手
已經改過的內容。

### 想在新一季開始前，先看看整季會是什麼樣？

撳選單「全季流程演練」，輸入季度 ID。系統會**唯讀為主**地跑一次完整
流程（讀職事表快照、產生團契、組裝每個主日的
週報資料模型、產生第一個主日的 Word 試看、組裝電郵內容但**不寄**、
檢查職事表分歧、統計待填欄位），把每一步的結果與耗時、全季總待填、
總警告、尊稱未設定人數、分歧衝突數，全部寫進 `Diagnostics`。

⚠️ 演練**不會寄出任何真郵件**（不論 `Config` 的 `DRY_RUN` 是什麼）；
但會產生一份**真實的** Word 檔（用來驗證整條產生鏈真的走得通），這份
檔案會留在輸出資料夾，需要人手清理。

## 出問題時去邊度看

系統有三張記錄工作表，加一份「完成度自我檢測」報告，出狀況時可以按
情況去查：

- **`SendLog`**：每一次寄送嘗試的記錄，一個收件人一行，可以看到
  「這封到底有沒有寄成功」「是不是試行」。
- **`ErrorLog`**：系統偵測到的例外狀況（例如收件人清單是空的、
  觸發器算出的日期不是星期日）。`SOURCE` 欄可以看出是伺服器、前端
  填寫介面，還是自動觸發器發生的問題。
- **`AuditLog`**：試算表本身的異動記錄，寄送成功時會在這裡看到
  `BulletinWeeks` 的狀態被改成 `SENT` 的那一筆。
- **`Diagnostics`**：每一次跑「檢查範本佔位符」「全季流程演練」
  「完成度自我檢測」「檢查職事表分歧」這類報告類選單，結果都會寫在
  這裡（每次覆蓋重寫，只留最新一次）。
- **Apps Script 專案的「執行項目」**：如果連 `ErrorLog` 都沒有記錄
  （例如整個腳本在載入階段就壞了），要去 Script Editor 的「執行項目」
  頁面看實際的例外堆疊。

**如果完全不確定系統現在狀態如何**，撳選單「完成度自我檢測」——這是
判斷「系統是否可以交付使用」的一站式報告，逐項列出設定、資料、功能、
記錄四大類的狀況，每項標 🟢（正常）／🟡（可運作但未完備）／🔴
（會令系統無法正常運作），對話框直接顯示三個數字的總計，完整清單寫進
`Diagnostics`。

如果「試寄下週週報」或自動寄送失敗，對話框（或 `ErrorLog`）通常會
講明原因，常見的幾種：

- **收件人清單是空的**：檢查 `Recipients` 工作表有沒有 `ACTIVE=TRUE`
  的行、`GROUP_NAME` 是不是在 `Config` 的 `SEND_GROUPS` 之內。
- **這個主日在職事表找不到資料**：確認職事表那一季已經生成、日期
  正確。
- **工作表結構落後於程式碼**：按選單「初始化工作表」補齊。未按之前，填寫介面的儲存、還原、重設都會被擋，星期一的自動寄送亦不會寄出（只在 `ErrorLog` 記一行）；所以每次部署新版
  （`clasp push`）之後，部署說明叫你按的話要即時按。
- **範本檔案不是 Word 檔**：多數是 Google Drive 把上載的 `.docx`
  自動轉換成 Google 文件格式——去 Drive 設定關閉「將上載的檔案轉換為
  Google 文件編輯器格式」，重新上載原檔。
- **MailApp 每日配額不足**：Google 帳戶每天可以寄出的郵件數量有
  上限，配額用完要等隔天。
- **訊息內含「這是授權範圍問題」**：代表帳戶的授權令牌不包含這次
  操作需要的服務（例如第一次用到 Word 範本功能時才第一次用到
  `DriveApp`）。按選單「檢查授權範圍」確認哪幾項未授權，再按選單
  「週報系統 ▸ 重新授權（新增權限之後用）」，在彈出的授權畫面按 Allow
  （或在 Apps Script 編輯器的函式下拉揀 `authorizeAllScopes` 再按執行；
  揀其他函式不會出授權畫面）——詳見
  [上線前檢查清單.md](上線前檢查清單.md)「第 0 步：確認授權範圍」。

## 系統出問題時，怎樣人手接手

即使填寫介面、選單或自動寄送暫時全部用不了，每個主日的週報仍然可以
靠「最新的 Word 檔」加上試算表完成。原則只有一條：Word 檔是成品，
試算表是資料；人手接手時直接改成品，事後再把改動補回資料。

### 第一步：找到這個主日的最新 Word

1. 開啟 `Config` 的 `BULLETIN_OUTPUT_FOLDER_ID` 指定的雲端硬碟資料夾，
   進入以季度 ID 命名的子資料夾（例如 `2027T4`），開啟
   `主日日期_粵語堂週報.docx`。每個主日只有一個檔案，就是最新版。
2. 填寫介面還能開啟的話，「發佈及匯出」的「開啟最新 Word 檔」與
   「開啟本季 Word 資料夾」兩條連結可以直達。
3. 星期一的郵件也附有當週的 Word 檔，同樣是最新版。
4. 想找回較舊的內容：在雲端硬碟對該檔案按右鍵 ▸「管理版本」，每一次
   更新都保留了舊版本。
5. 找不到檔案（從未產生過）：到 `BulletinWeeks` 工作表看該主日那一行
   的各欄資料，連同上一個主日的 Word 檔作底稿，人手改成這個主日的內容。

如果系統完全不能產生 Word，需要自己從範本做起，三個 Word 範本的檔案
ID 記在 `Config` 的這三個鍵：

| Config 鍵 | 範本 |
|---|---|
| `TEMPLATE_FILE_ID_NORMAL` | 平常主日 |
| `TEMPLATE_FILE_ID_COMBINED_BAPTISM` | 浸禮三堂聯合崇拜 |
| `TEMPLATE_FILE_ID_ANNIVERSARY` | 堂慶三堂聯合崇拜 |

### 第二步：人手修改

直接在 Word 內改文字（程序表、事奉名單、獻花、講題、經文、公告等）。
改完先另存一份新檔名（例如在檔名後面加「_人手」），不要覆蓋系統的
那一份——系統稍後如果恢復，再按一次「下載 Word」或選單「產生本週週報」
會把同名檔案更新成系統版本，人手改動就會被蓋走。

### 第三步：輸出與交付

1. 印刷：把改好的 `.docx` 交付印刷，與平日相同。
2. 要發佈 PDF：在 Word 另存為 PDF，再到「master 連結」那個檔案（檔案 ID 在
   `Config` 的 `PUBLISHED_PDF_FILE_ID`）右鍵 ▸「管理版本」▸「上載新版本」。
   這樣教會網站上的連結不變。
3. 已發佈的 PDF 與存檔副本在哪裏：目前對外發佈的 PDF 就是上面那個 master
   檔案；每次發佈另存的帶日期與版本號的副本放在 `Config` 的
   `PUBLISHED_ARCHIVE_FOLDER_ID` 指定的資料夾，`PublishLog` 工作表每一次
   發佈有一行，記錄版本號、時間與副本檔案。
4. 要寄給堂委與執事：用幹事自己的電郵寄出，收件人名單見 `Recipients`
   工作表（`GROUP_NAME` 欄分組）。

⚠️ 如果自動寄送觸發器仍然有效，而你已經人手寄出，請先把 `Config` 的
`DRY_RUN` 改為 `TRUE`（或在選單移除自動寄送觸發器），以免星期一系統再
自動寄一次。人手接手結束後記得改回原狀。

### 第四步：系統恢復後，把改動補回資料

人手改動只存在於 Word 檔內，試算表並不知道。系統恢復後，請在填寫介面
把同樣的改動再填一次，否則下次重新產生 Word 時，內容會回到舊版。

### 三個方便人手接手的位置

| 要找的東西 | 在哪裏 |
|---|---|
| 這個主日的週報資料 | `BulletinWeeks` 工作表，一個主日一行 |
| 誰收週報 | `Recipients` 工作表 |
| 寄過沒有、發佈過沒有 | `SendLog`、`PublishLog` 工作表 |

## 直接修改事奉名單

填寫介面的「本週事奉」區塊可以**直接改**——每個崗位每個位次一個輸入
框，改完撳「儲存」即可。

⚠️ **在這裡改動的名單只存在週報，永遠不會寫回職事表。** 系統一格職事表
都不會寫。如果職事表本身要改，請自行到職事表更正。

幾個要知道的行為：

- **沒有改動過的崗位，會自動跟隨職事表最新版。** 職事表那邊改了人，
  週報下次載入就會跟著變，不需要你做任何事。
- **按「儲存」只會送出你在這一頁改過的事奉格。** 這一頁開着期間職事表換了人，
  你只改其他欄位（例如序樂）再儲存，不會把畫面上的舊名字變成覆寫；儲存之後
  畫面重新載入，就會見到職事表的新名字。只改其他欄位亦不會令「衝突」消失。
- **改動過的崗位，職事表之後再改也不會蓋過你的修改。** 系統只會把它
  標示為「衝突」，讓你自己決定要不要跟。
- 改動過的格子左邊會有一條**橙色直線**，旁邊有「還原」按鈕可以一鍵改回
  職事表的值；格子旁邊的灰色細字會顯示職事表現時的值。已經儲存了覆寫的格子按「還原」
  再儲存，一律改回跟隨職事表：即使這一頁開着期間職事表換了人（輸入框顯示的是載入時的
  名字），儲存之後畫面重新載入，顯示的是職事表現在的名字，不會變成新的覆寫。
- **衝突**的格子會用**紅底**，並同時列出三個值：你覆寫當時職事表是誰、
  職事表現在是誰、你的覆寫值是誰。處理方法有三個，處理完按「儲存」：
  - 仍然要用你的名字：按「保留我的」（按鈕變成「取消保留」，再按一次就撤回），
    儲存之後紅色提示消失，系統記下職事表現在的名字作新的對照；
  - 改用職事表的名字：按「還原」；
  - 改成另一個人：直接改名字。
  按了「保留我的」之後再改名字或按「還原」，保留會自動撤回；先按「還原」再按「保留我的」，
  輸入框會填回你的名字（保留的就是那個名字）。
  如果職事表已經改成與你的名字相同，不會有「保留我的」，旁邊會講明下次儲存會
  自動改回跟隨職事表，不用另外處理。「下週事奉」一框亦一樣。
- 事奉框有未儲存的改動（改了名字、按了「保留我的」或「還原」）時按「重讀職事表（本主日，不覆寫）」，
  會先問「重讀職事表會丟失你未儲存的事奉改動，確定嗎？」。按「取消」甚麼都不做，改動仍在；按「確定」
  就按職事表最新內容重畫事奉框，改動丟失。沒有改動時照舊直接讀。
- 把輸入框**清空**，或者改回與職事表相同的值，就等於**取消覆寫**——
  那一格會改回跟隨職事表。（`DutyOverride` 工作表的記錄不會被刪除，
  只是標成無效，日後仍然查得到。）
- 覆寫的姓名如果對得上 `PersonDisplay` 的姓名，尊稱（弟兄／姊妹／
  牧師……）照樣會自動加上；對不上（例如臨時幫忙的訪客）就原樣顯示，
  這是正常的，不是錯誤。

## 自動寄送觸發器的細節

「安裝自動寄送觸發器」會依 `Config` 的 `SEND_WEEKDAY`（星期幾）與

## 崇拜程序：一個主日一行（內容表 v2，2026-10）

內容表「崇拜程序」分頁**一個主日一行**，每個主日已經預先開好一行（系統建立或刷新內容表時開好，
值由週報帶入），請直接改那一行，不要另加一行。以前的「宣召」「浸禮合堂」兩張分頁已併入這裏。

| 欄 | 誰填 | 留空的意思 |
|---|---|---|
| 讀經經文、證道講題 | 講員（多數已有權限，可以自己開內容表填；沒有權限的交給幹事代填） | 待填清單會列出 |
| 序樂、詩歌頌讚、回應詩歌 | 領詩 | 序樂留空＝週報印 Config `PRELUDE_DEFAULT` |
| 詩班曲名 | 詩班負責人 | 週報那一行整行不印 |
| 宣召出處、宣召經文 | 幹事 | 待填清單會列出 |
| 浸禮六欄 | 幹事（只填浸禮合堂那一個主日） | 其餘主日留空是正常的 |
| 有效、備註 | ——（備註是內容表內部備忘，不會匯入） | |

「誦讀（覆寫）」「詩班項目名稱」「程序表大標題」「程序範本」不在內容表，只在填寫介面填。

⚠️ 「讀經經文」是經文出處，**不是**讀經的人——讀經那位肢體由職事表決定，在事奉框顯示為「讀經」。

### 兩邊都改得到，怎樣決定用哪一個？

「崇拜程序」每一欄都是**第三種模式**：內容表為來源，但填寫介面改得到。填寫介面甲區塊頂那一條會寫
「本區內容來自內容表「崇拜程序」……在這裏改等於覆寫，之後匯入不會蓋過」。

| 情況 | 匯入之後 |
|---|---|
| 你沒有在介面改過 | **跟隨內容表最新值** |
| 你在介面改過 | **保留你填的**，匯入報告會寫「沒有蓋過」，並列出內容表現在是甚麼 |
| 你想改回跟隨內容表 | 把介面那一格**改成與內容表相同**，覆寫就會自動取消 |

⚠️ 所以如果同工說「我明明改了內容表，為甚麼週報沒有跟着變」——多數就是那一格已經被覆寫。按
「從內容表匯入（整季）」看預覽，「沒有蓋過」那一段會逐格列出來。

### ⚠️ 舊版內容表要先移轉一次

2026-10 之前建立的內容表是舊版（有「宣召」「浸禮合堂」兩張分頁、「崇拜程序」只有七欄）。舊版內容表
**匯入會被整次拒絕**（「本季內容表比系統舊……請先按「建立／刷新本季內容表」」），重設這一週亦一樣。

在填寫介面「季度作業」按「建立／刷新本季內容表」，預覽會講明：「崇拜程序」加幾欄、由舊「宣召」搬入幾個主日、
由舊「浸禮合堂」搬入幾個主日、由週報回填幾格（只填空白格）、新增幾行、幾格兩邊不同（保留崇拜程序的值）、
兩張舊分頁會改名為「（已停用）」並隱藏、不會刪除。**看清楚預覽才按確定。** 移轉可以重複按，第二次會講
「已經是新版，沒有需要移轉」。星期一的自動流程不會替你移轉。

### 內容表的第 2 行與欄位次序

系統按欄位位置讀內容表，所以匯入之前會核對每張分頁第 2 行（機器鍵）。第 2 行被改過、或者有人插入、刪除、
移動過欄，匯入會整次拒絕，並講明是哪一張分頁第幾欄；請用「檔案 ▸ 版本記錄」復原。格子被試算表自動轉成
日期／時間（例如「3:16」變成時間）時，那一格這一次不匯入並出警告，請把格式改回純文字再重新輸入。

崇拜程序（一個主日一行）、家事報告、代禱事項、本週團契聚會、月度財政報告、上週崇拜人數，
**由講員、領詩、堂委、執事與幹事在另一個試算表輸入**。**一季一個檔案**，放 Shared Drive。

⚠️ 家事報告、代禱事項、團契、財政、崇拜人數以內容表為**唯一編輯來源**，填寫介面那幾個區塊是唯讀——要改就去
內容表，然後按「重新匯入」。「崇拜程序」各欄則兩邊都改得到（見上面「崇拜程序：一個主日一行」）。

### 每季開始前：建立內容表

按填寫介面「季度作業 ▸ 建立／刷新本季內容表」（或選單「週報系統 ▸ **內容表 ▸ 建立本季內容表**」，
兩邊都先顯示預覽，按確定才做）。系統會：

1. 在 Config `CONTENT_SHEET_FOLDER_ID` 指定的資料夾建立一個試算表，
   名叫「週報內容_季度」
2. 開好七張分頁：`_說明`、崇拜程序、家事報告、代禱事項、團契聚會、財政報告、
   崇拜人數（內容表 v2）；「崇拜程序」每個主日預先開好一行，值由週報帶入
3. 把「主日日期」欄設成下拉選單，選項就是該季全部主日
4. 把檔案設成**網域內任何人可編輯**
5. 在該季第一個主日預填一組**樣本**，讓大家一看就知道格式與長度

**第一次用之前**要先在 `Config` 填兩格：

| 設定鍵 | 填什麼 |
|---|---|
| `CONTENT_SHEET_FOLDER_ID` | 那個 Shared Drive 資料夾的 ID（在瀏覽器打開資料夾，網址 `/folders/` 後面那一串） |
| `CONTENT_SHEET_DOMAIN` | 教會的 Google Workspace 網域（就是大家教會電郵 `@` 後面那一串）。內容表會分享成「這個網域內任何人可編輯」 |
| `CONTENT_SHEET_ADMIN_CONTACT` | 你的聯絡方法，會印在內容表的 `_說明` 分頁 |

沒填 `CONTENT_SHEET_FOLDER_ID` 的話，系統會停下來並講明要填哪一個鍵，
不會亂建立。沒填 `CONTENT_SHEET_DOMAIN` 的話檔案照樣建立得到，但分享權限
要你自己人手設（對話框會提你）。

⚠️ 這三格**沒有預設值**，因為這個 repo 會公開到 GitHub，真實的資料夾 ID、
網域、聯絡方法一律不可以寫進原始碼。

### 已經建立過的，再撳一次會怎樣

**不會重建。** 系統只會補回缺少的分頁、欄位、新增的主日、下拉選單，
然後回報「**已更新，未重建**」——堂委已經填好的東西**一格都不會動**。

所以職事表加了一個主日之後，可以放心再撳一次，下拉選單就會跟著更新。

### 把連結寄給堂委與執事

撳「**內容表 ▸ 寄出內容表連結**」。信裏面有：內容表連結、本季主日清單、
每張表由誰負責、截止日期，以及「不要刪行、不要改前兩行」的提醒。

收件對象由 Config `CONTENT_SHEET_INVITE_GROUPS`（預設 `CC,DB,ADMIN,IT`）
決定。⚠️ **受 `DRY_RUN` 保護**——`DRY_RUN=TRUE` 時不會真的寄出，但照樣
在 `SendLog` 留記錄，可以先試一次看看內容。

**新季度快到時系統會自動寄。** 距離該季第一個主日少於
`CONTENT_SHEET_INVITE_LEAD_DAYS`（預設 21 日）而且未寄過的話，每星期的
自動寄送流程會順手建立內容表並寄出邀請。**同一季只會寄一次。**

### 要告訴堂委與執事的三件事

內容表的 `_說明` 分頁已經寫了，但寄信時最好口頭再提一次：

1. **不要刪行。** 不要那一行，就把最後一欄「有效」改做 `FALSE`。
   刪了行之後，系統對不回之前匯入過什麼。
2. **不要改第 1、2 行。** 第 1 行中文標題、第 2 行機器鍵，改了其中一格
   整張表就匯入不到。資料由第 3 行開始填。
3. **日期只能用下拉選單揀。** 手打的日期系統認不到，會被拒絕。

### 幾個容易搞錯的地方

- **「連續到」**（家事報告、代禱事項獨有）：要連登幾個星期的報告**只需要
  輸入一次**——在「主日日期」填第一次出現那個主日，在「連續到」揀最後
  一次出現那個主日。留空＝只出現在「主日日期」那一週。
- **`崇拜人數` 的「崇拜日期」是崇拜當日**，不是週報那個主日。週報自己會
  找「該主日減七天」那一行。所以下拉選單裏會多了該季第一個主日之前那個
  星期日——該季第一期的人數就填在那裏。
- **`團契聚會` 的「日期」「時間」是純文字**，照你想印出來的樣子打就可以
  （`28/11 星期日`、`4:30pm`），系統不會自動轉格式。
- **`財政報告` 有兩種表輪流出現**：綜合收支（四個數字欄都填）與特殊海外
  奉獻及慈惠基金（**只填「欄一」「欄二」**）。「報告標題」留空時系統會
  用預設的綜合收支標題。
- **樣本行**：首個主日那幾行是系統預填的樣本，確認格式之後請自行修改，
  或者把「有效」改為 `FALSE`。

### 把內容表的資料搬入週報：匯入

堂委與執事填好之後，由你按一次匯入。**兩個入口，做的是同一件事**：

| 入口 | 範圍 |
|---|---|
| 試算表選單「週報系統 ▸ **從內容表匯入**」 | **整季**全部主日 |
| 填寫介面每個唯讀區塊上方的「**重新匯入**」 | **只有目前選中的那一個主日** |

兩個入口都會**先顯示差異**：

```
將會新增 3 行　將會修改 1 行　將會刪除 0 行　不變 12 行
```

下面列出前 20 行明細（哪一張表、哪一個主日、哪一個欄位、舊值 → 新值）。
**完整明細一定會寫入 `Diagnostics` 工作表**，可以慢慢核對。看清楚之後按
「是」才會真的寫入；按「否」就一格都不會改。（填寫介面的「重新匯入」是頁內對話框：
按「確定」才寫入，按「取消」顯示「已取消，一格都沒有寫。」。）

⚠️ 「刪除」不會真的刪走任何一行，只是把那一行的「有效」改為 `FALSE`。

### 匯入時要留意的幾點

- **內容表某一張分頁整張空白 → 那一張完全不動**，報告會寫「家事報告：
  內容表沒有資料，本次不改動」。這是刻意的保護：萬一有人不小心清空一張
  分頁，系統不會把整季內容清光。
- 反過來，如果那一張分頁**有資料**、只是某一週沒有任何一則，那一週既有的
  行就會被停用——這樣才刪得走一週的最後一則。
- **「連續到」會自動展開**：一條由 10-03 連登到 10-24 的報告，四個主日都會
  各出現一行。即使只匯入其中一個主日，這條報告一樣會出現。
- **崇拜人數對應的是「崇拜日期 + 7 天」那一期**。如果加七天之後不是本季的
  主日，那一行會被略過，並在報告列出。
- 匯入**不受 `DRY_RUN` 影響**——`DRY_RUN` 管的是「會不會寄信給人」，匯入
  只是把資料由一張表搬到另一張表。對話框仍然會註明目前是不是模擬模式。
- 匯入之後，填寫介面那七個區塊上方會顯示最後匯入時間。

### 為什麼填寫介面那七個區塊改不到

因為內容表已經接管了它們。如果在那裏改，下一次匯入就會被蓋回去——與其
讓你白做，不如直接改成唯讀。

真的想改，去內容表改，然後按「重新匯入」。如果按了「儲存」而系統彈出
「這七項內容已改由內容表輸入」，代表你的瀏覽器用的是舊版介面，
**重新整理一次頁面**就可以。

## 版本記錄、還原與重設這一週

填寫介面「版本記錄（這一個主日）」區塊預設摺疊，展開才載入。每個主日各有自己的版本記錄。

### 系統什麼時候自動存版本

每次動手改這個主日的內容之前，系統都會先存一個版本，只有「真的會改到」才存：

- 在填寫介面按「儲存」（有改動才存；沒有任何改動的儲存不產生版本）；
- 從內容表匯入（整季或只匯入一個主日）、補抓空白的事奉欄位、由職事表重新取數；
- （以前亦包括季度填寫表的同步與講員表格的答案；內容表 v2 起兩者已停用，不再寫入週報）；
- 重設與還原之前；
- 產生 Word 之後另存一個，記下當時的內容和 Word 檔案連結（內容和上一次產生時完全相同就不再多存）。

舊版本不會刪除。列表只顯示最新 20 個（Config 的 `SNAPSHOT_LIST_LIMIT`）。

### 列表怎樣看

每一行：時間｜由誰（電郵只顯示 @ 之前）｜原因｜摘要。「產生 Word 之後」那幾行附 Word 檔連結，開啟的是這個主日
雲端硬碟上現時最新的那一份。區塊上方另有這個主日的發佈記錄（第幾版、時間、存檔副本連結），標明「已發佈」。

### 看差異

按該行的「看差異」，逐項列出「這個版本的值｜現在的值」，包括事奉框覆寫和在介面改過的欄位（例如講題、讀經經文），欄名一律用介面上的中文名稱。

### 還原到某個版本

1. 按該行的「還原到這個版本」。
2. 頁內對話框列出會改動哪些項目。表單上有未儲存的改動時，對話框會提醒還原後這些改動會丟失。
   按「取消」（或 Esc）會顯示「已取消，一格都沒有寫。」，甚麼都不會改。
3. 按確定之後，系統先自動存一個「還原之前」的版本，再把週報欄位改回該版本的值（只寫有差異的格），事奉框覆寫和在介面改過的欄位
   也改回與該版本相同（多出來的停用，缺的補回，不刪行），最後重新載入這一週。完成訊息用與列表相同的寫法
   稱呼版本，例如「已還原到版本「2026-10-21 19:43（填寫介面儲存）」：…」。
4. 揀錯了版本，可以到列表找那個「還原之前」的版本再還原一次。

不會還原的東西：狀態、寄出時間、Word 檔案 ID 這些系統欄；內容表接管的欄位；家事報告、代禱、團契、財政
（以內容表為準，要改請到內容表，試算表本身也有版本記錄）。

### 重設這一週

按區塊內的「重設這一週…」。對話框會列出五件事：

1. 先自動存一個版本，之後可以在版本記錄還原；
2. 這一週所有人手填的欄位改回建立時的預設值（例如序樂的範本預設值）；
3. 這一週的事奉框覆寫（包括上一週「下週事奉」改到這一週的）、在介面改過的欄位（例如講題、讀經經文）全部停用（不刪行）；
4. 如果本季已有內容表，由內容表重新匯入這一週；
5. 職事表一格都不會改；已發佈的 PDF、已寄出的郵件、已產生的 Word 檔都不受影響。

按「取消」同樣顯示「已取消，一格都沒有寫。」。

⚠️ 版本存不到的時候，重設和還原會整個中止，一格都不寫。一般的儲存則不受影響，但訊息會提醒「這次改動不能用還原找回」。

### 見到「伺服器沒有回應（…），這個動作可能已經完成」

還原、重設、發佈／寄出、匯入、補抓、由職事表重新取數、季度作業這類會寫入的動作，
如果網絡或 Google 那一邊斷了線（例如 HTTP 502），伺服器很多時仍然在處理，之後亦可能已經做完。
這時頁頂忙碌列會寫「伺服器沒有回應，等候 20 秒讓伺服器完成，然後重新載入…」，期間按鈕（包括
發佈前檢查視窗的按鈕和勾選格）不可以按；20 秒之後顯示紅色的一句，例如：

「伺服器沒有回應（apiResetWeek），這個動作可能已經完成。系統已重新載入這一個主日，請先看「最後儲存
時間」和「版本記錄」。如果仍未見到結果，伺服器可能仍在處理，請等 5 分鐘再重新載入核對，不要即時
再做一次。」

請先核對，不要即時再按：看頁頂「最後儲存時間」有沒有更新，展開「版本記錄」看有沒有新的一行（還原和
重設會先存一個「還原之前」／「重設這一週之前」的版本）。仍未見到就等 5 分鐘再重新載入看一次。
季度作業的按鈕會叫你看那一個區塊，亦只重新載入那一個區塊。還原、重設、匯入、補抓、
由職事表重新取數會重新載入這一週（與成功時一樣），表單上未儲存的改動會被換走。

發佈與寄出按你這一次勾了甚麼講核對的地方：發佈看頁頂「目前已發佈」的主日、版本和發佈時間；
寄出在填寫介面沒有記錄，要看試算表的 `SendLog`，而且「不要即時再寄，以免重複寄信」。發佈沒有回應
時不會重新載入這一週，表單上未儲存的改動會保留。兩樣都勾而只發佈了、未寄出的話，再做時只勾「寄出」。
同一期、同一組收件人 10 分鐘內（Config 的 `SEND_ONLY_DEDUP_SEC`，預設 600 秒）再寄一次，系統會擋下並講
「剛才已經寄出過這一期（…）的通知（…），為免重複，這次沒有再寄。……」——剛才「發佈加寄出」已經寄了的，
只寄出亦會被擋下。

如果是等了 120 秒仍然沒有回應（逾時），句子是：「伺服器在 120 秒內沒有回應（動作名稱），伺服器可能
仍在處理（最長約 6 分鐘）。請等 6 分鐘後重新載入頁面，再看〈地方〉核對，不要即時再做一次；亦可請
IT 看 Apps Script 的「執行項目」。」。

如果自動重新載入本身亦失敗，那一句後面會多「重新載入亦失敗，請稍後按 F5 重新整理。」。

「儲存」不一樣：不會等，也不會重新載入，你在畫面上的改動原封不動，訊息是「伺服器沒有回應
（apiSaveWeek），儲存可能已經完成，你的改動仍在畫面上。請再按一次「儲存」：如果系統說「這一週的
資料在你載入之後被改過」，即是上一次已經存好，重新載入這一週就會見到。」。照做再按一次「儲存」
是安全的：伺服器一次只做一個儲存，第二次要等第一次寫完才讀，上一次已經存好的話，系統會擋下這一次，
一格都不會重複寫；上一次沒有到達的話，這一次就會存好。逾時（120 秒）的話，句子改講「伺服器可能仍在
處理，……請等一兩分鐘才再按「儲存」」。如果見到「另一個寫入動作（例如另一次儲存、匯入或發佈）正在
執行中，30 秒內等不到，所以這一次一格都沒有寫。……」，稍等再按「儲存」即可。

### 其他會見到的幾句

- 讀取資料（載入、看差異、報告）等了 120 秒仍然沒有回應：「伺服器在 120 秒內沒有回應
  （函式名稱）。這是讀取資料，沒有改動週報內容；請稍後重新載入頁面再試。」——週報內容沒有改過，
  放心重新載入（有幾個載入會順手寫系統記錄，例如職事表跟隨記錄，重複做沒有問題）。
- 「下載 Word」等了 120 秒：「……Word 檔沒有下載到；請稍後再按一次「下載 Word」。伺服器可能已經更新了
  雲端硬碟上這一期的最新 Word，再按一次只會原地更新同一個檔案，不會多出一份。」
- 「Google 登入狀態有問題（HTTP 401 或 403），這個動作沒有送到伺服器。請重新載入頁面；如果用了多個
  Google 帳戶，請只登入教會帳戶再試。」——這一次一定沒有做，重新登入之後再做一次是安全的。
- 按「還原到這個版本」、「重設這一週…」或「由職事表重新取數」的確定之後見到「另一個寫入動作（例如另一次
  儲存、匯入或發佈）正在執行中，30 秒內等不到，所以這一次一格都沒有寫。請稍等再按「…」。」：這一次甚麼都
  沒有做（與儲存那一句同一個意思），等一會再按即可。這三個動作與儲存、匯入、發佈排隊，一次只做一個。
- 會寫入的確認對話框（重設、還原、重新匯入、由職事表重新取數、發佈前檢查、季度作業）
  按「取消」一律顯示「已取消，一格都沒有寫。」（發佈前檢查視窗按過「確認發佈」之後除外，見下面
  「發佈」一節）。
- 兩個分頁同時開着時：在一個分頁「由職事表重新取數」、改「本週事奉」或「下週事奉」、還原或重設之後，
  另一個較早載入、顯示同一批事奉名字的分頁（同一週，或者它的「下週事奉」是這一週）按「儲存」，會收到
  「這一週的資料在你載入之後被改過……」。重新載入那一頁再改即可——這是為了不讓舊分頁把剛才的改動
  蓋回去。

- 「季度工具 ▸ 停用舊功能」會拆走表單提交觸發器，並把表格設為停止收件；講員打開舊連結會見到
  Config `SPEAKER_FORM_CLOSED_MESSAGE` 那一句（預設「講員資料改為在內容表「崇拜程序」填寫，請聯絡幹事。」）。
  表格本身與舊答案（`SpeakerFormSubmissions`）都不會刪除。
- 停用之前萬一仍然收到答案：只記一行 `SpeakerFormSubmissions`（處理結果「講員表格已停用，沒有寫入」），
  照 `DRY_RUN` 通知管理員，**不寫內容表、不寫週報**；請把內容抄進內容表「崇拜程序」。
- 填寫介面已經沒有「講員表格」區塊；週報不再出「講員表格填的講員是……」那一個核對警告。
- 「上線前檢查」與「完成度自我檢測」的「講員表格」一項：從未建立，或者觸發器已拆、表格已停止收件＝🟢；
  仍然有觸發器或仍然收件＝🟡（請按「停用舊功能」）。

## 發佈週報：一條永遠不變的連結

會眾看的是一條**永遠不會變**的連結。它指向 Shared Drive 內一個固定的
PDF 檔案；每次發佈是**覆寫那個檔案的內容**，不是換一個新檔案，所以連結
可以印上教會網站、加入書籤，之後每星期打開都是最新一期。

### 第一次設定（整個系統只需要做一次）

**第 1 步：啟用 Drive 進階服務。**

⚠️ 這一步不做，發佈一定會失敗，錯誤訊息會叫你回來做這一步。

1. 在試算表按「擴充功能 ▸ Apps Script」開啟編輯器
2. 左邊「服務」旁邊按 **＋**
3. 清單裡選 **Drive API**，識別碼保持 `Drive`（不要改），按「新增」
   ⚠️ 版本選 **v2**（`src/appsscript.json` 釘的就是 v2；本專案用的是
   v2 的檔名欄位 `title`，換成 v3 要一併改程式碼，見 docs/待確認事項.md M-1）
4. 按上方的儲存圖示

為甚麼一定要它：Apps Script 內建的 `DriveApp` **只寫得到文字**，把 PDF
餵給它會寫出一個打得開但內容是亂碼的檔案。要原地覆寫一個 PDF 的二進位
內容，只有進階服務做得到。

⚠️ 系統對 Drive 的每一個呼叫都會自動帶上「連共用雲端硬碟一起處理」那個
參數。這件事**不用你做**，寫在這裏只是因為它曾經是一次事故的原因：缺了
它，Drive 會對一個明明存在的檔案回「找不到檔案」（見 docs/已知bug類型.md
事故二十四）。

**第 2 步：填兩個資料夾 ID。** 在 `Config` 工作表填：

| 設定鍵 | 填甚麼 |
|---|---|
| `PUBLISHED_PDF_FOLDER_ID` | master 檔案要放在哪一個資料夾 |
| `PUBLISHED_ARCHIVE_FOLDER_ID` | 每期存檔副本放在哪一個資料夾 |

資料夾 ID 怎樣拿：在瀏覽器開啟那個資料夾，網址 `/folders/` 後面那一串
就是。

**第 3 步：按選單「週報系統 ▸ 建立 master 發佈檔案」。**

系統會建立一個佔位 PDF、把它設成「知道連結的人可檢視」、把檔案 ID 自動
寫回 Config，然後顯示三條連結：

| 連結 | 給誰用 |
|---|---|
| 檢視 | 一般會眾。放上教會網站的就是這一條 |
| 內嵌 | 想把週報直接嵌在網頁裡面時用 |
| 下載 | 想把 PDF 存落電話的人 |

**把「檢視」那一條交給網站管理員。之後永遠不用再換。**

⚠️ 這個選單項目按過一次就不用再按。再按只會顯示同樣那三條連結，
**不會**重建——重建等於換掉連結，網站上那一條就會失效。

### 每星期發佈

```
1. 在填寫介面把這一期填好
2. 按「下載 Word」
3. 用 Word 開啟，最後核對一次版面
4. 在 Word 按「另存新檔」，格式選「PDF」
5. 回到填寫介面，在「發佈及匯出」勾選要做甚麼，選那個 PDF，按「執行」
```

第 3、4 步是唯一不能自動化的一步：Apps Script 轉出來的 PDF 會令 A5 版面、
文字方塊與那 18 款字型走樣，而會眾看的就是這一份，不能走樣。順帶的好處
是多了一道人手覆核——發出去的東西一定有人親眼看過。

### 「發佈及匯出」區塊怎樣用

兩個勾選**各自獨立**，三種組合都可以：

| 勾了甚麼 | 結果 |
|---|---|
| 只勾「發佈到 master 連結」 | 覆寫 master 檔案、存一份副本，**不寄任何郵件** |
| 只勾「寄出」 | 只寄通知信（信裡是 master 連結），**不碰 master 檔案**。通知信的日期是 master 連結現時那一期（頂部狀態列「目前已發佈」那一期），不一定是你選中的主日 |
| 兩個都勾 | 先發佈，再寄出，通知信可以順便附上這一次的 PDF |

- 兩個都沒有勾就按「執行」→ 會提示要至少勾一個，甚麼都不會做。
- 勾了發佈但沒有選 PDF → 會提示先選檔案。
- 「寄出」與收件對象會**記住**你上一次的選擇（存在你自己的瀏覽器帳戶偏好，
  不會影響其他人）。**「發佈到 master 連結」每次載入都是未勾選**——發佈會
  覆寫網站上的 master 連結，每次都要你當下自己勾。
- 「只勾寄出」而系統從未發佈過任何一期 → 會拒絕，並叫你先發佈一次。
- 「只勾寄出」而選中的主日不是 master 連結現時那一期 → 寄出前檢查會多一行
  「⚠ 目前 master 連結是 某日（第 N 版）的週報，不是 選中的日期；這次寄出的
  通知會指向 某日。要寄 選中的日期 的週報，請先勾「發佈到 master 連結」。」
  要勾方框才可以繼續。收件人收到的信，主旨和內文的日期都是 master 那一期，
  與連結打開看到的一致。`SendLog` 的狀態記 `SEND_ONLY`（發佈加寄出才記
  `PUBLISH`）。寄出前檢查視窗開着期間有人發佈了新一期，通知會指向新一期，
  結果會多一行「⚠ 寄出前檢查之後，master 連結已經換成 某日（第 N 版）（另一次發佈
  剛剛完成），所以通知信指向 某日，不是寄出前檢查講的 某日（第 N 版）。」
- 收件對象勾 IT／CC 堂委／DB 執事／幹事／我自己，另外可以在「自訂電郵」
  填地址（逗號分隔）。**有任何一個地址格式不對，整次寄出會取消並逐個列
  出來**——不會靜靜跳過，那種錯沒有人會發現。
- 橙色的「模擬模式開啟中」橫幅出現時，寄出**只會記錄，不會真的寄**（見
  下面 `DRY_RUN` 的說明）。
- 「執行」之後區塊下面顯示的結果只屬於那一個主日：換到另一個主日（下拉、
  「上一個／下一個」、換季）結果會收起；同一個主日重新載入（例如發佈、還原
  之後）會保留。換週之後見不到結果，不代表那一週已經寄出或發佈，要看頂部
  狀態列或 `SendLog`。
- 已選的 PDF 同樣只屬於揀檔那一個主日：換到另一個主日會清走，旁邊改回「未選擇」，
  要重新揀這一週的 PDF。如果仍然拿另一週揀的 PDF 去發佈，會被擋住並提示
  「揀檔之後換了主日，請重新揀這一週的 PDF。」，一格都不會寫。

### 想看目前發佈出去的是哪一份？

用**頂部狀態列**那一顆「開啟目前已發佈的 PDF」，它會用新分頁開啟 master
檔案。

⚠️ 它刻意是「**開啟**」而不是「下載」，而且刻意放在狀態列、不放在「發佈
及匯出」區塊裏面。原因是實際發生過的一件事：幹事在發佈區塊按了「下載
目前已發佈的 PDF」，然後在下一步選檔案時把**同一個檔案**選回去上載——
等於用舊內容覆寫自己，而且畫面照樣回報「已發佈第 N 版」，沒有人會發現
那一期其實沒有更新。

現在就算真的選錯，系統也會擋住並講明：

- 「你選的是目前已發佈的那一份，請選用 Word 另存的新 PDF」
- 「你選的是佔位檔，不是週報」

想看**這一期**的內容，用「下載 Word」。

### 發佈前檢查

按「執行」之後，如果這一期有未填欄位、或者日期有異常，會先彈出一個檢查
視窗，把問題**全部列出來，不會截斷**：

- **未填欄位**：分成程序、人數、家事報告、代禱事項、團契聚會、事奉人選
  幾組逐項列出。這份清單跟填寫介面頂部那個「待填 N 項」是**同一份**：
  兩處的人數 12 格都合併成一行「人數：N 格未填（上週崇拜人數由內容表輸入）」，
  數字都按格數計。
- **日期提醒**，三種可以同時出現：
  - 這一期的主日已經過去
  - 這一期不是下一個主日（會講出下一個是哪一天）
  - 上一次發佈之後有主日未發佈（會講出範圍與數目）

三種都**不會阻止你發佈**——補發舊一期、預先發佈下下星期，都是真實會發生
的事。但要親手勾「我明白以上情況，仍然要發佈」才能按「確認發佈」，而且
這件事會記進 `PublishLog`（`是否強制發佈 = TRUE`，連同當時的問題摘要）。

沒有任何問題的話，這個視窗不會出現，按「執行」就直接做。

### 頂部那一行「目前已發佈」

填寫介面頂部常駐一行：

```
目前已發佈：2027-11-07（第 3 版）　2026-08-22 10:04 由 ivan 發佈　[開啟]
```

它**不隨主日下拉改變**——它講的是「master 連結裡面現在放的是哪一期」，
不是「你正在看哪一期」。從未發佈過會顯示「尚未發佈過任何一期」；還沒有
建立 master 檔案會顯示「尚未建立 master 發佈檔案」並提示去選單建立。

### 撳了「執行」之後沒有反應？

- 按鈕會立刻變成「發佈中…」並停用，**這是正常的**，代表系統收到了。
- 完成之後按鈕會變回「執行」，並在區塊下方顯示結果。
- 如果**同一個主日在 30 秒內**（Config `PUBLISH_DEDUP_SEC`）撳了兩次，
  第二次會回「剛才已經發佈過（第 N 版），這一次沒有再產生新版本」——
  版本號不會白白多跳一級，通知信也不會多寄一封。
- 如果見到「另一個發佈或匯入正在執行中」，代表有另一個動作正在寫入。
  等一等再按一次即可。
- 如果見到「伺服器沒有回應（apiRunPublish），這個動作可能已經完成」
  （連線中斷，系統會先等 20 秒再顯示）：⚠️ 這一種情況跟
  「失敗」**不同**——它代表**不知道有沒有做完**。系統已重新載入頂部狀態列
  （不會重新載入這一週，表單上未儲存的改動保留），
  請先看「目前已發佈」有沒有變、版本記錄的「已發佈」有沒有新的一版（只寄出
  的話看試算表的 `SendLog`），仍未見到就等 5 分鐘再核對，不要即時重按。
  等了 120 秒仍然沒有回應的話，句子改講「伺服器可能仍在處理（最長約 6 分鐘）。
  請等 6 分鐘後重新載入頁面……」。
- 只寄出時，同一期、同一組收件人在 10 分鐘內（Config 的 `SEND_ONLY_DEDUP_SEC`，
  預設 600 秒；發佈本身的防重複仍是 `PUBLISH_DEDUP_SEC`）再按一次（包括剛才
  「發佈加寄出」已經寄了的），會見到「剛才已經寄出過這一期（…）的通知（…），
  為免重複，這次沒有再寄。如果真的要再寄一次，請 10 分鐘之後再按。」——一封都
  沒有再寄。時窗改了的話，最後一句跟着講（不足一分鐘就講秒）。模擬模式
  （`DRY_RUN=TRUE`）寄過的一批不會擋住正式寄出：模擬試完、把 `DRY_RUN` 改成 `FALSE`，
  可以即時正式寄出；正式寄過的一批則會擋住之後的模擬。
- 發佈前檢查視窗未按「確認發佈」就按「取消」，會顯示「已取消，一格都沒有寫。」
  （沒有發佈、沒有寄出）。按了「確認發佈」之後、未有結果之前，「取消」會停用；
  有了結果（包括「伺服器沒有回應……」或者紅色的失敗）之後按「取消」只會關閉視窗，
  頁頂保留原本那一句——那時可能已經發佈或寄出了，不會講「一格都沒有寫」。

### 發佈失敗時

錯誤訊息會講明是哪一種，處理方法完全不同：

| 訊息 | 怎樣處理 |
|---|---|
| Drive 進階服務尚未啟用 | 回去做上面「第一次設定」的第 1 步 |
| 找不到那一個檔案 | master 檔案被刪或被搬走了。⚠️ 重新建立會產生**新的連結**，教會網站上那一條要一併更新 |
| 沒有寫入該檔案的權限 | 叫 Shared Drive 管理員把執行帳戶加到「內容管理員」 |

⚠️ 覆寫失敗時 `PublishLog` **不會**多一行——沒有成功就不算發佈過。

如果訊息說「存檔副本未能寫入」，那是**另一回事**：master 已經換好了，
會眾看到的已經是新一期，只是少了一份帶日期的副本，人手補存一份就可以。

## 自測機：兩粒掣，一份報告

⚠️ 這一節是給**維護程式碼的人**看的，一般填寫週報用不到。

系統有一套「自己測自己」的工具，放在選單「週報系統 ▸ 測試工具」。
你只需要記住兩粒掣。

### 掣一：〔跑一次不變量檢查（唯讀）〕

**這一粒零風險，隨時可以按。** 它只是看一眼系統現在的狀態，一格都不會改。

它會檢查十件「任何時候都必須成立」的事，例如：

- 畫面上顯示的每一個數字，由工作表重新數一次，數不數得到同一個數
- 頂部狀態列說「已發佈第 3 版」，master 連結裡面那一份**真的**是第 3 版嗎
- 產出的 Word 檔裡面還有沒有沒換掉的 `{{ }}`
- `DRY_RUN=TRUE` 之下，`SendLog` 有沒有混進真實寄出的紀錄
- 職事表的版本記錄有沒有多過（本系統對職事表一律唯讀）

結果分**三種**，不是兩種：

| 標示 | 意思 |
|---|---|
| ✅ | 查過，成立 |
| 🔴 | 查過，**不成立**——這是要處理的 |
| ⚪ | **驗證不到**（服務未啟用、檔案讀不到、還沒有資料可以驗） |

⚠️ **⚪ 不等於 ✅。** 「驗證不到」的意思是「這一刻沒有辦法確認」，
不是「沒有問題」。報告會逐條講明為甚麼驗不到。

完整結果寫在 `Diagnostics` 的「不變量檢查」報告。

### 掣二：〔跑自測（沙盒季度，DRY_RUN）〕

**這一粒會寫東西，但只寫沙盒季度。** 按下去之前它會先問你一次。

它會由**真實入口**（跟你自己按選單完全同一條路）跑十八個情境：建立空白
週報 → 建立內容表 → 寫幾條家事報告 → 匯入 → 再匯入一次看是不是零改動 →
儲存 → 產生 Word → 發佈 → 寄出（試行）……每一個情境跑完，再檢查一次上面
那十條不變量。

**四道安全鎖**（任何一道不成立就一步都不跑）：

1. `DRY_RUN` 必須是 `TRUE`。
2. 只寫 `Config` 的 `SELFTEST_QUARTER_ID` 那一季（預設 `2030T1`，
   刻意選一個職事表沒有資料的季度）。
3. 那一季不可以等於 `SELFTEST_ROSTER_QUARTER_ID`（需要真實資料時只讀
   那一季）。
4. 職事表全程唯讀，跑完會比對版本記錄行數確認。

⚠️ **每次開跑會把沙盒季度（`2030T1`）的資料清乾淨**，令每次都由同一個
起點開始。那一季本來就是拿來測試的，不會影響任何真實資料。

**跑不完會怎樣**：Apps Script 有 6 分鐘上限。時間到它會**乾淨停低**，
並在報告寫明「跑到 S07，還有 11 個未跑」——然後按〔繼續跑自測〕接住。
它**不會**靜靜停低然後扮成跑完了。

**報告怎樣看**：紅色的一定連「預期甚麼、實際甚麼、證據是甚麼」三樣一齊
印出來。另外有一段「略過」——那是前置條件未滿足（例如未設定沙盒 master
發佈檔案），報告會明寫**「略過」不等於「通過」**。

### 另外那一粒：〔⚠️ 亂行機〕

進階用的，一般不需要按。它會在沙盒季度內**隨機**執行合法的動作（改格、
匯入、產生、發佈……），每走一步檢查一次全部不變量，用來抓「沒有人想過
要這樣按」造出來的問題。

它會問你要走幾多步（預設 50），然後你可以去做別的事。

如果紅了，報告最重要的一行是「**走到這裏的完整步驟**」——照著那一串再
按一次就重現得到。報告開頭那個「亂數種子」也要留住：先按〔跑自測〕把
沙盒清乾淨，再用同一個種子跑一次，就會走同一條路。

### 第一次用之前

在 `Config` 確認（或填寫）這幾格：

| 設定鍵 | 填甚麼 |
|---|---|
| `SELFTEST_QUARTER_ID` | 保持 `2030T1`（除非那一季真的會用到） |
| `SELFTEST_ROSTER_QUARTER_ID` | 一個**有真實職事表資料**的季度，預設 `2027T4` |
| `SELFTEST_MASTER_PDF_FILE_ID` | 選填。另外建立一個測試用的 PDF 檔案，填它的 ID。**留空的話發佈那三個情境會被略過**（自測機絕對不會碰正式那一個 master 檔案） |

## 更新程式碼：`deploy.bat`（一鍵部署）

⚠️ 這一節是給**維護程式碼的人**看的，一般填寫週報用不到。

repo 根目錄有一個 `deploy.bat`，在 Windows 上雙撳（或者在命令列跑）
就會依次做完五件事，**任何一步失敗就立即停止並講明原因**：

| 步 | 做什麼 |
|---|---|
| 1 | `clasp push --force`　把 `src/` 推上 Apps Script |
| 2 | `git add -A` |
| 3 | `git commit`　（沒有任何改動就自動略過，不算失敗） |
| 4 | `git push`　推上 GitHub |
| 5 | `clasp deploy`　更新 Web App 部署 |

用法：

```
deploy.bat "這次改動的說明"
```

括號內那句會同時用作 commit 訊息與部署說明。不給參數的話會用預設訊息。

### 第一次用之前：建立 `deployment-id.txt`

`deploy.bat` **不會**把部署 ID 寫在檔案內（原始碼一律不放真實 ID）。
要在 repo 根目錄自己建立一個 `deployment-id.txt`：

- 內容：**一行**，只放 Web App 的部署 ID，不要加引號。
- 那個 ID 在 **Apps Script ▸ 部署 ▸ 管理部署作業** 取得。
- 這個檔案已經列入 `.gitignore`，**永遠不會被 commit 上 GitHub**。

檔案不存在時 `deploy.bat` 會直接停下來，並在畫面印出上面這段指示。

### 跑完之後仍然要人手做一件事

畫面最後會提醒：

```
仍需人手：試算表 ▸ 週報系統 ▸ 初始化工作表
```

**新增了 Config 設定鍵或者 `BulletinWeeks` 欄位之後，一定要撳一次**，
否則新欄位不會出現在試算表上。這個動作是冪等的（撳幾多次都一樣，
不會清走任何既有資料），不確定的時候撳多一次最穩陣。

## 名詞解釋

### `DRY_RUN`（試行模式）

`Config` 工作表的一個設定值，`TRUE` 或 `FALSE`：

- **`TRUE`（系統預設，建議平常保持這個值）**：執行寄送流程時，系統
  會做完全部檢查（收件人、內容、配額……），也會在 `SendLog` 留一筆
  記錄，但**完全不會呼叫寄信服務、不會有任何人收到郵件**。
- **`FALSE`**：寄送流程走到最後一步時**真的會寄出郵件**給每一位
  收件人。

`SendLog` 工作表的「是否試行」欄會清楚記下每一筆記錄是不是試行產生
的，方便事後查核。

### 衝突

**同一格內容，兩邊都被改過，系統不知道應該以哪一邊為準。** 有兩個
地方會出現「衝突」這個概念：

1. **週報覆寫 vs 職事表**：幹事在週報直接覆寫過某個崗位的人選，之後
   職事表那邊又改了同一個崗位——系統不會自動選邊，只會標示衝突。
   在事奉框那一格按「保留我的」（保留你的名字）、按「還原」或者改名字再儲存，
   亦可以按「由職事表重新取數」逐項確認。只改其他欄位儲存，衝突不會消失。
2. （已停用）**季度填寫表 vs 系統（`BulletinWeeks`）**：內容表 v2 起季度填寫表已停用，不再有這一種衝突。
   內容表與填寫介面之間的「沒有蓋過」見上面「崇拜程序：一個主日一行」。

兩種衝突的共同原則：**系統一格都不會自動改**，兩邊的值都完整保留，
一定要人手決定。

### 覆寫

幹事在週報（填寫介面）直接改動某個崗位的事奉人選，跟
職事表當時的值不一樣，就叫「覆寫」。覆寫只影響週報顯示，**永遠不會
寫回職事表**；記錄在 `DutyOverride` 工作表，供日後查核與判斷是不是
衝突。

### 快照

系統用來判斷「自從上次一致之後，是哪一邊改過」的**基準值**——單純比較
「兩邊現在的值是不是一樣」是不夠的，因為兩邊不同可能代表「只有一邊
改過」（正常同步）或者「兩邊都改過」（衝突），沒有基準值分不出這兩種
情況。`FillSnapshot` 工作表存的是季度填寫表與系統之間的快照（內容表 v2 起已停用，不再更新）；
`BulletinWeeks` 的 `ROSTER_SNAPSHOT_VERSION` 存的是週報與職事表之間
的快照（版本號形式）。快照由系統自動維護，人手不需要、也不應該直接
改動它。
