# 幹事操作說明

本文件寫給每星期實際操作「週報系統」的幹事看，說明每星期要做什麼、
選單各個項目的用途、`DRY_RUN` 是什麼意思，以及自動寄送觸發器的限制。
技術細節（工作表結構、程式架構）請見 [工作表結構.md](工作表結構.md)。

---

## 每星期大致的流程

1. **填寫內容**：撳試算表選單「週報系統 ▸ 開啟填寫介面」，在網頁介面
   填好本週的崇拜程序、人數、家事報告、代禱事項、團契、財政等資料。
   詳細操作見填寫介面本身的說明；每一格填完撳「儲存」即可，不需要
   額外的動作。事奉名單如果要臨時改動，同樣可以在這個介面直接改——
   見下方「直接修改事奉名單」一節。
2. **核對內容**：撳選單「預覽週報郵件內容」，看看這一週的郵件會長
   什麼樣子——事奉框、程序表、人數表等有沒有明顯錯漏。這個動作
   **不會寄出任何郵件**，可以隨時撳、撳幾次都沒關係。
3. **試寄確認**：撳選單「試寄下週週報（依 DRY_RUN 設定）」。如果
   `Config` 的 `DRY_RUN` 是 `TRUE`（系統預設），這個動作**不會真的
   寄出郵件**，只會在 `SendLog` 工作表留一筆記錄，方便你確認「如果
   現在真的寄，會寄給誰、寄幾封」。
4. **正式寄送**：確認內容無誤之後，如果想現在立刻寄出（不等自動
   觸發器），把 `Config` 的 `DRY_RUN` 改成 `FALSE`，再撳一次「試寄
   下週週報」——這一次就會**真的**寄出。寄完記得把 `DRY_RUN` 改回
   `TRUE`，避免下次操作不小心真的寄出。
5. **自動寄送（選用）**：如果希望系統每星期自動寄送，撳一次選單
   「安裝自動寄送觸發器」即可，之後不需要每星期手動操作第 4 步——
   但仍然建議定期用「試寄」「預覽」核對內容，因為自動寄送不會幫你
   檢查內容對不對，只會照 `DRY_RUN` 現在的值執行。

⚠️ **`DRY_RUN` 是全系統共用的一個開關**，不是「這一次操作要不要試行」
的選項。如果你安裝了自動寄送觸發器，觸發的時候也是看 `DRY_RUN` 目前
的值——**如果你為了手動測試把 `DRY_RUN` 改成 `FALSE` 之後忘記改回
`TRUE`，下一次自動觸發也會是真的寄送**。建議養成習慣：測試完立刻
改回 `TRUE`。

## 選單項目說明

試算表選單「週報系統」新增的項目（跟本文件相關的挑出來說明；其餘
項目屬於系統維護，一般操作用不到）：

| 選單項目 | 用途 | 會不會真的寄出郵件 |
|---|---|---|
| 開啟填寫介面 | 開啟網頁版填寫介面 | 不會 |
| 檢查職事表分歧 | 問一個主日日期，比對週報與職事表，結果寫入 `Diagnostics` | 不會 |
| 預覽週報郵件內容 | 問一個主日日期，顯示郵件內容 | **不會** |
| 試寄下週週報（依 DRY_RUN 設定） | 問一個主日日期，執行一次寄送流程 | **依 `DRY_RUN`** |
| 安裝自動寄送觸發器 | 設定每星期自動執行寄送 | 觸發時依 `DRY_RUN` |
| 移除自動寄送觸發器 | 取消每星期自動寄送 | 不會 |
| 查看觸發器狀態 | 列出目前安裝了哪些觸發器 | 不會（唯讀） |

## 直接修改事奉名單

填寫介面的「本週事奉」區塊可以**直接改**——每個崗位每個位次一個輸入
框，改完撳「儲存」即可。

⚠️ **在這裡改動的名單只存在週報，永遠不會寫回職事表。** 系統一格職事表
都不會寫。如果職事表本身要改，請自行到職事表更正。

幾個要知道的行為：

- **沒有改動過的崗位，會自動跟隨職事表最新版。** 職事表那邊改了人，
  週報下次載入就會跟著變，不需要你做任何事。
- **改動過的崗位，職事表之後再改也不會蓋過你的修改。** 系統只會把它
  標示為「衝突」，讓你自己決定要不要跟。
- 改動過的格子左邊會有一條**橙色直線**，旁邊有「還原」按鈕可以一鍵改回
  職事表的值；格子旁邊的灰色細字會顯示職事表現時的值。
- **衝突**的格子會用**紅底**，並同時列出三個值：你覆寫當時職事表是誰、
  職事表現在是誰、你的覆寫值是誰。
- 把輸入框**清空**，或者改回與職事表相同的值，就等於**取消覆寫**——
  那一格會改回跟隨職事表。（`DutyOverride` 工作表的記錄不會被刪除，
  只是標成無效，日後仍然查得到。）
- 覆寫的姓名如果對得上 `PersonDisplay` 的姓名，尊稱（弟兄／姊妹／
  牧師……）照樣會自動加上；對不上（例如臨時幫忙的訪客）就原樣顯示，
  這是正常的，不是錯誤。

### 「由職事表重新取數」

撳這個按鈕**不會立即改動任何東西**，而是彈出一個比對對話框：

- 只列出你改動過的欄位（衝突的、以及已覆寫但職事表沒再改過的）
- 每行一個勾選框，衝突的行**預設勾選**，其餘**預設不勾選**
- 上方有「全選」「全不選」
- 撳「確定」之後，**只有勾選的欄位**會被職事表的值覆蓋，你在那幾格的
  修改會被清除（記錄仍然保留）

如果週報與職事表完全一致，對話框會直接說「週報與職事表一致，沒有需要
取數的欄位。」

### 頂部的「衝突 N 項」

有衝突時這個數字會變紅色，撳一下可以展開清單。衝突的意思是：**你在
週報改過那一格之後，職事表那邊又改過**——系統不知道應該以哪一邊為準，
所以只提醒你，不會自動決定。

系統也會在每星期自動寄送週報**之前**，把新出現的衝突用電郵通知
`Recipients` 中 `ADMIN` 組的人（可以在 `Config` 的
`CONFLICT_NOTICE_GROUPS` 改成別的組別）。**同一個衝突只會通知一次**，
除非職事表又再改過——避免每星期收到同一封提醒。

## `DRY_RUN` 是什麼

`DRY_RUN`（試行模式）是 `Config` 工作表的一個設定值，`TRUE` 或 `FALSE`：

- **`TRUE`（系統預設，建議平常保持這個值）**：執行寄送流程時，系統
  會做完全部檢查（收件人、內容、配額……），也會在 `SendLog` 留一筆
  記錄，但**完全不會呼叫寄信服務、不會有任何人收到郵件**。這是用來
  「確認流程會不會出錯」的安全模式。
- **`FALSE`**：寄送流程走到最後一步時**真的會寄出郵件**給每一位
  收件人。

`SendLog` 工作表的「是否試行」欄會清楚記下每一筆記錄是不是試行產生
的，方便事後查核。

## 自動寄送觸發器

### 運作方式

「安裝自動寄送觸發器」會依 `Config` 的 `SEND_WEEKDAY`（星期幾，例如
`MONDAY`）與 `SEND_HOUR`（幾點，24 小時制）設定一個每週執行一次的
時間觸發器，執行的函式會：

1. 用今天的日期加上 `Config` 的 `SEND_TARGET_OFFSET_DAYS` 天，算出
   「要寄哪一個主日」（預設是星期一觸發、加 6 天＝下一個主日）。
2. 確認算出來的日期真的是星期日——如果不是（通常代表
   `SEND_WEEKDAY`／`SEND_TARGET_OFFSET_DAYS` 兩個設定互相對不上），
   系統**不會亂猜**，會直接放棄這一次，並在 `ErrorLog` 留一筆記錄。
3. 執行跟「試寄下週週報」完全相同的寄送流程（一樣看 `DRY_RUN`）。

### ⚠️ 不保證準時執行

Apps Script 的時間觸發器**只能指定「小時」，不能指定「分鐘」**，而且
**不保證準確在該小時執行**——實際觸發時間可能比預定時間晚數十分鐘，
甚至更久。`Config` 的 `SEND_MINUTE` 只是給人看的規劃參考，**系統本身
沒有辦法真的用它來排程**。

如果星期一早上 8 點設定，實際寄出的時間有可能是 8 點多，也可能
接近 9 點——這是 Google Apps Script 平台本身的限制，不是本系統的
bug。如果你發現寄送時間跟預期差太遠（例如晚了幾個小時以上），可以
用「查看觸發器狀態」確認觸發器還在，或者查看 Apps Script 專案的
「執行項目」紀錄。

### 重複安裝不會變成寄兩次

「安裝自動寄送觸發器」每次執行都會**先刪除全部既有的同名觸發器，
再建立一個新的**，所以就算不小心連續撳好幾次「安裝」，最後也只會
有一個觸發器，不會變成一星期收到好幾封重複的週報。

## 出錯了怎麼辦

系統有三張記錄工作表，出狀況時可以按情況去查：

- **`SendLog`**：每一次寄送嘗試的記錄，一個收件人一行，可以看到
  「這封到底有沒有寄成功」「是不是試行」。
- **`ErrorLog`**：系統偵測到的例外狀況（例如收件人清單是空的、
  觸發器算出的日期不是星期日）。`SOURCE` 欄可以看出是伺服器、前端
  填寫介面，還是自動觸發器發生的問題。
- **`AuditLog`**：試算表本身的異動記錄，寄送成功時會在這裡看到
  `BulletinWeeks` 的狀態被改成 `SENT` 的那一筆。

如果「試寄下週週報」或自動寄送失敗，對話框（或 `ErrorLog`）通常會
講明原因，常見的幾種：

- **收件人清單是空的**：檢查 `Recipients` 工作表有沒有 `ACTIVE=TRUE`
  的行、`GROUP_NAME` 是不是在 `Config` 的 `SEND_GROUPS` 之內。
- **這個主日在職事表找不到資料**：確認職事表那一季已經生成、日期
  正確。
- **工作表結構落後於程式碼**：撳選單「初始化工作表」補齊。
- **MailApp 每日配額不足**：Google 帳戶每天可以寄出的郵件數量有
  上限，配額用完要等隔天。

三份週報 `.docx` 原檔目前還沒有提供，所以每一封郵件目前都**沒有 PDF
附件**，郵件正文本身就是完整的週報內容全文，供堂委、執事、幹事
先行審閱；日後範本準備好，流程會自動多出一個 PDF 附件，正文內容
不會因此減少。
